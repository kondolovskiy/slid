## Знахідки

### Блокувальні

**B1. Тест меж модулів ловить лише один синтаксис імпорту.**
`server/test/architecture.spec.ts:20`: регулярний вираз `/from\s+'(\.[^']+)'/g` бачить лише `from '…'` в одинарних лапках. Я додавав у `src/modules/progress/progress.controller.ts` імпорт внутрішнього файлу `identity` у різних формах, запускав `npx jest test/architecture.spec.ts` і щоразу відновлював файл з копії (`cmp` підтвердив, що файл ідентичний оригіналу):

| Порушення | Результат тесту |
|---|---|
| `import { IdentityService } from '../identity/identity.service'` | ✕ впав (ловить) |
| те саме в кілька рядків | ✕ впав (ловить) |
| `import { IdentityService } from "../identity/identity.service"` (подвійні лапки) | ✓ 19/19 — **пропущено** |
| `require('../identity/identity.service')` | ✓ — **пропущено** |
| `import '../identity/learner.store'` (імпорт заради побічного ефекту) | ✓ — **пропущено** |
| `import('../identity/learner.store')` (динамічний) | ✓ — **пропущено** |

У проєкті немає ні prettier, ні eslint, тож подвійні лапки цілком можуть з'явитися в коді. Крім того, `docs/BACKEND.md:40–44` називає перевіреними тестом ще два правила, яких тест не перевіряє взагалі:
- «через порт, а не клас сервісу»: якби `index.ts` експортував `IdentityService`, тест би це пропустив;
- «жодних запитів у чужу схему»: `withSchema('identity')` у `progress` тест теж пропустить.

Також не перевіряються файли поза `modules/` (`src/app.ts`, `src/db/migrate.ts`).
**Як виправити:** шукати будь-який рядковий літерал відносного шляху в `from`/`import(`/`require(`/`import '…'`, тобто `/(?:from|import|require)\s*\(?\s*['"](\.[^'"]+)['"]/g`. Додати перевірку, що `withSchema('<x>')` трапляється лише в модулі `<x>`. У docs чесно вказати, яке правило перевіряє тест, а яке — лише рев'ю. Найкраще додати до самого тесту негативний приклад (фікстуру з порушенням, яку тест мусить відхилити), щоб він не міг тихо стати хибно-зеленим.

**B2. Документація стверджує, що сервер не отримує клас дитини, але `grade` зберігається.**
`docs/BACKEND.md:8`: «Імені, email, телефону, класу/школи сервер не отримує». Насправді `server/src/modules/progress/progress.service.ts:18` вирізає лише верхньорівневе `name`. Стан `slid.v1` (`docs/ARCHITECTURE.md:34`, `app/app.js:104`) містить `grade`, `planByGrade`, `weekOverride`, `theme`. Відтворення на запущеному `dist`:
`PUT /v1/progress {"rev":4,"data":{"name":"Оля","grade":5,"profile":{"name":"Оля"}}}` → `200 {"rev":5,"data":{"grade":5,"profile":{"name":"Оля"}}}`.
Мінімум персональних даних — пряма вимога людини, тож розбіжність між документацією й кодом тут блокувальна. **Як виправити:** або вирізати `grade` (а прогрес за класами без нього, можливо, не має сенсу), або виправити docs: «клас зберігається як частина стану; імені немає». Друге — це рішення людини, тож питання варто винести у «Відкриті питання». У будь-якому разі варто перейти від чорного списку (`name`) до явного білого списку ключів стану, які сервер приймає. Тоді нове поле на кшталт `school`, додане у фронтенді, не потрапить на сервер непомітно.

**B3. Значення від клієнта викликають 500 замість 400.**
- `rev` перевіряється лише як `Number.isInteger(rev) && rev >= 0` (`server/src/modules/progress/progress.input.ts:8`), а колонка має тип `integer` (`server/src/modules/progress/migrations.ts:10`). `{"rev":3000000000}`, `{"rev":2147483647}` (у запиті стає `rev+1`) і `{"rev":1e300}` дають **500**; у лозі — `value "3000000001" is out of range for type integer`.
- `{"rev":0,"data":{"s":"\u0000"}}` дає **500**, бо Postgres `jsonb` не приймає `\u0000`.

Будь-який клієнт може викликати серверну помилку, а логи засмічуються стеками. **Як виправити:** у `parseProgressInput` обмежити `rev < 2**31 - 1` (або взяти `bigint` і сказати про це в docs) і відхиляти `\u0000` у серіалізованому JSON (одна перевірка `json.includes('\\u0000')`). Додати обидва випадки в `progress.input.spec.ts`.

### Бажані (не блокують)

**P2-1. «Винесення — лише заміна адаптера» описано неточно.** `server/src/modules/progress/progress.module.ts:8` імпортує конкретний `IdentityModule`, з його контролером і `PgLearnerStore`. Тому крок 2 у `docs/BACKEND.md:50` («у моноліті замість `IdentityModule` підключаємо клієнтський модуль») не спрацює, якщо змінити лише `AppModule`: `ProgressModule` однаково підтягне `IdentityModule`. Насправді заміна має відбутися в `modules/identity/index.ts` (експортувати під іменем `IdentityModule` клієнтський модуль із тим самим токеном `IDENTITY` і `LearnerGuard`). Код `progress` при цьому справді не зміниться. Варто так і написати в docs. Альтернатива — щоб `ProgressModule` не імпортував `IdentityModule`, а `IDENTITY` надавав глобальний модуль-адаптер.

**P2-2. CI не перевіряє `npm run migrate` із `dist`.** Задача заявляє, що працюють `npm run build && npm run migrate`, але `.github/workflows/server.yml:35–38` запускає міграції лише через e2e (з `src` через ts-jest). Пропуск шляху в `dist` або помилка в `require.main` CI не помітить. Варто додати крок `- run: npm run migrate` після `build`. Я перевірив цей шлях вручну, див. нижче.

**P2-3. Прогалини e2e.** Немає тестів на 413 (тіло понад 512 КБ), на `data` понад 256 КБ через HTTP, на межі `rev` (B3) і на гонку на гілці UPDATE: гонку покрито лише для `rev: 0`, тобто для INSERT. Сам я UPDATE-гонку перевірив (нижче), але регресійного тесту немає.

**P3-1.** `POST /v1/learners` не потребує автентифікації й нічим не обмежений: будь-хто може без кінця додавати рядки в `identity.learners`. Це вже є в «Що далі», п. 4. Перед будь-яким публічним деплоєм цей пункт обов'язковий.

**P3-2.** `X-Powered-By: Express` у відповідях. Дрібниця, але `app.disable('x-powered-by')` — це один рядок у `src/app.ts`.

**P3-3.** `MemoryProgressStore.get` повертає внутрішній об'єкт за посиланням (`server/src/modules/progress/progress.store.ts:40`), хоча `compareAndSet` клонує. Тест, який змінить результат `get`, змінить і саме сховище. Зараз жоден тест так не робить.

**P3-4.** Memory-адаптери лежать у продакшн-файлах `*.store.ts` і потрапляють у `dist`. Так зроблено свідомо («для локальних експериментів»), але тоді краще позначати їх в `index` як тестові або винести в `*.memory.ts`.
