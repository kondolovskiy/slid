### P1-2 (блокувальна). `form: "factored"` і `form: "reduced"` не помічають невинесеного або нескороченого числового множника
- `app/learn.js:489–513`: `factorCount` не рахує сталі множники. `fracDeg` і `exprForm` порівнюють лише степені.
- Відтворення (очікувано `form`, фактично `ok`):
  - `expression "3x(x+2)", form factored` ← `x(3x+6)` і `(3x+6)·x`;
  - `expression "5x(x-2)", factored` ← `x(5x-10)`;
  - `expression "4(x+1)(x-1)", factored` ← `(2x+2)(2x-2)`;
  - `expression "2(x+3)", factored` ← `(2x+6)·1`;
  - `expression "(x-1)(x+1)", factored` ← `(x^2-1)^2/(x^2-1)` (множники в знаменнику не враховано);
  - `expression "2x/3", form reduced` ← `6x/9`; `"(x+1)/2"` ← `(2x+2)/4`; `"3a/(4b)"` ← `6a/(8b)`; `"1/(x+1)"` ← `2/(2x+2)`.
- Чому це блокує: «винеси спільний множник» (g7m3) і «скороти дріб» (g8m1) якраз і перевіряють числову частину спільного множника. CONTENT_SCHEMA.md:301–302 обіцяє «повний розклад» і «нескоротний дріб». Автор згадує лише `4(0,5x + 1)`, але `x(3x+6)` — найчастіша неповна відповідь.
- Що пропоную: для многочлена з раціональними коефіцієнтами вимагати, щоб кожен множник зі змінною мав примітивні цілі коефіцієнти (НСД = 1). Для `reduced` порівнювати НСД числових коефіцієнтів чисельника й знаменника. Множники в знаменнику не зараховувати до `factored`.

### P3 (небажані відхилення правильних записів, дрібні неузгодженості)

## Що працює правильно (перевірено мною)
- ratio: порядок, рівні відношення, `reduced` → `form`, від’ємні й нульові члени → `bad`, три члени.
- coordinates2: переставлені координати й інший знак → `bad`; `(1,5, 2)` → `bad`, `(1,5; 2)` / `(3/2; 2)` → `ok`; інша кількість компонент → `bad`.
- exactRoot: наближення (`3,4641`, `3.4641016151377544`, `1,5708`) → `bad`; `√12`, `1/√2`, `√18` → `form`; `√3·2`, `2sqrt(3)`, `0,5π`, `π:2` → `ok`.
- list з ±: одна гілка → `bad`, наближення → `bad`, будь-який порядок → `ok`.
- intervalSet: інша відкритість кінця, `[-∞`, a > b, нерівність замість проміжку → `bad`; злиття суміжних частин, `[3;3]` = `{3}`, `R` = `(-∞; +∞)`, `{}` = `∅`.
- periodicSet: інший період, `(-1)^(k+1)`, одна серія замість двох, `±π/3+πk` → `bad`; `n`/`m`, `x =`, `k є Z`, `π(2k+1)/2` → `ok`.
- expression: `|x|` / `√(x²)` ≠ `x`; рівняння прямої й кола пропорційні; `y = …` проти правої частини; `-x^2` ≠ `(-x)^2`; `X` ≠ `x`.
- Безпека: `constructor`, `__proto__`, `toString`, `alert(1)` → `bad` без винятку; `eval`/`Function` не використовуються; винятків у жодному з ~400 моїх випадків не було.
