## Знахідки

### P1-1. Катастрофічний бектрекінг у новій `NAME_AT` (кубічний час на пробілах)
`app/learn.js:687`:
```
... ([a-z]))\s*([→⃗])?\s*(=?)\s*(?=\()
```
Три `\s*` поспіль, між якими лише необов'язкові групи. Коли запис не закінчується на `(` після назви, рушій перебирає всі способи поділити пробіли між трьома `\s*`, тобто O(N³). У старій версії було `\s*(=?)\s*`, тобто O(N²), і це практично непомітно.

Відтворення: `NAME_AT.exec("c" + " ".repeat(N) + "x")`, лише сама регулярка, Node 22:

| N пробілів | стара | нова |
|---|---|---|
| 1000 | 1 мс | 444 мс |
| 2000 | 4 мс | 2971 мс |
| 4000 | 18 мс | 24 282 мс |

Через `checkAns` (B4 чи точка B, запис `c` + N пробілів + `x`, NAME_AT викликається кілька разів): 1000 пробілів — 0,8 с (стара версія — 2 мс), 2000 — 6,2 с (стара — 9 мс), 5000 — понад 190 с. Це стосується будь-якої вправи `coordinates2`/`coordinates3`, не лише векторних, і великих назв так само (`AB` + пробіли).

Регулярка синхронна, тож межа `limited`/кроків її не перериває. Поле відповіді не має `maxlength` (app/app.js:1090). Отже, вставлений чи довгий запис заморожує вкладку. Регресія порушує інваріант обмеженої роботи перевірки (у test-learn є `bounded` і `WALL_MS`), а тести її не ловлять.

Пропоноване виправлення (перевірено: лінійний час, 100 000 пробілів — 0 мс; групи 1–5 ті самі, «=» → `"="` або `undefined`, а код і так перевіряє `!m[5]`):
```
\s*(?:([→⃗])\s*)?(?:(=)\s*)?(?=\()
```
Ще потрібен тест у test-learn: запис з тисячами пробілів між назвою й не-«(», час < ~100 мс. Варто перевірити й інші регулярки цього блоку на той самий шаблон (`VEC0` у tools/diff-answers.mjs:196 має таку саму будову, але це інструмент — P3).

### P3-1. Мутант, що вижив: умова `!vnames.size` у заголовку
`app/learn.js:749`: якщо замінити `!names.size && !vnames.size` на `!names.size`, test-learn лишається зеленим (2628/2628). Бракує фікстури, де тіло питає вектор малою (`вектора $\vec{c}$`), а заголовок називає іншу назву.

### P3-2. Стрілка після назви точки
`B→(3; -2)` і `B→ = (3; -2)` при «Знайди координати точки $B$» тепер `ok` (раніше `bad`). У CONTENT_SCHEMA це описано («і для великих назв»), значення правильне, хибного ok для неправильних координат немає. Нотація для точки дивна, але шкоди немає. Залишаю на розсуд.

### P3-3. `\vec c` без дужок у записі дитини
`\vec c = (…)` дає `bad`, тоді як `\vec{c} = (…)` дає `ok` (`vecBraces` застосовано лише до умови). Дитина TeX навряд чи набиратиме, тож це лише відомість.

## Що перевірено щодо фокусу
- **Чи не приймає неправильне.** Власні проби (scratchpad `probe.mjs`), окремо стара й нова версії:
  - точки без вектора малою: `b = `, `b→`, `\vec{b} = ` дають bad, як раніше; `b(…)` — ok, як раніше.
  - точка B в умові з `$\vec{a}(…)$`: `b = ` і `c→` — form «тут шукають B»; `a(…)`/`a = ` — form «даний вектор»; `B = ` — ok.
  - B4: `c==`, `c→→`, `c→=→`, `cc =`, `c(…)(1)`, `c = (…) + 0`, неправильні значення — усі bad без підказки; великі `C =`, `A(…)`, `AB =` — ok (відома межа, задокументована).
  - символьний ключ з векторами малою: `v(…)`, `p(…)` — bad (множник); `k→(…)`, `\vec{v}(…)`, `m = (…)` — ok (m тут змінна, не даний вектор).
  - `$2\vec{a}$`: `a = (2; 4)` — form «a — даний вектор»; `a = (1; 2)`, `2a = (…)` — bad.
- **Підказки не видають ключ:** нові тексти (`vaskMsg`, `givenMsg` для малої) містять лише назву з умови, без чисел; вони є в `hintTexts`.
- **diff-answers:** нові категорії «vec …» класифікують за текстом умови (`vecNames`) і за вердиктом **старого** рушія на записі без назви чи стрілки, тож від нового рушія вони незалежні. Записи з довгими пробілами туди не входять, тому P1-1 diff-answers не ловить.
- **Мутанти (власні, копія дерева в scratchpad) проти test-learn:** given → 9 падінь; `vec` без given-малих → 17; прибрати `plain || !ask` → 2; прибрати `symPair` у dropName → 1; вимкнути гілку малої → 23; `vnames.delete` → 2; vaskMsg у hintTexts → 1; порядок `vask`/`ask` у nameMsg → 4; заголовок `!vnames.size` — **вижив** (P3-1).
