### P1-1. Підказка обіцяє «торкнись місця», а для кількох точок тап нічого не робить

## Що перевірено як коректне
- `largestRemainder`: усі нулі → нулі; один сектор → [100]; 1/1/1 → 34/33/33; 1/1/4 → 17/17/66; похибка плаваючої коми `x + 1e-9`; від'ємні значення відсікає `Math.max(0, …)` у bars.
- `if`: двокрапки в гілках (`if:так: ось;ні` → «так: ось»), одна гілка, `;`-перевищення, порожній аргумент (помилка validate), NaN → друга гілка, 0 → друга.
- `eq`: `0.1+0.2` → «= 0,3»; `-0.0001` → «≈ 0»; `eq:0` 2,5 → «≈ 3»; великі числа; ∞ → «?»; `eq:ab` → помилка validate.
- `\{ \}`: `\frac{\{1\}}{2}`, `x^{\{2\}}`, `\text{a\{b}`, `\left\{ x \right\}`, `\{2; 3\}` — групи `{…}` не ламаються.
- solid segs/cut: нумерація вершин у docs збігається з `solidGeom` (box 0–7, prism 2n, pyramid n+1). Точка з невизначеними координатами пропускається, а не малює NaN.
- Тап: не заважає перетягуванню (після тапу ручка переходить у `drag`), не чіпає клітинки цифр і `tap`-ручки, фокус переходить на ручку (стрілки далі рухають ту саму точку). Для кількох ручок поводиться як раніше.
- Колесо: обробник висить лише на `#dock` (усередині `#player`), довгий `#fbText` прокручується сам. Інші екрани не зачеплено, test-ui зелений.
- Зміст: g10m1, g10m3, g11m1, g8m3, pg8m1, pg11m1 переведено на нові формати, статус → draft. У g10m1l1 рядок зі значенням `y` прибрано, координати показує точка P (`coords: true`).
