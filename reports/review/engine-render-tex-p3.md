## engine-render-tex-p3

**app/lab.js (P3-1, P3-2).** `svgTex` / `svgMathR(src, size, carry)`: незакритий dy після формули тепер віддається тексту (`$a_n$(2; 3)` → `<tspan dy="-3">(2; 3)</tspan>`) або наступній формулі (`$a_n$$b_m$` → `b` з dy=-3). Формула в кінці — без зайвого tspan. `$x^{ab}$ t` → `dy="4"`. Рахунок `reset = r - d` для вкладеного індексу правильний (`x_{a_b}`: -5). На змісті — байт у байт. Мутації: `carry = 0` → 5 падінь test-lab; `reset = -d` → 1 падіння. Тести xmlEsc є.

**app/app.js (attr, SUB, urlAttr).** Відтворено в Chromium (функції з app.js на живій сторінці):
- `attr(esc(t))` подвійного екранування **немає**: `A & B` → aria-label «A & B»; `a<b` → «a<b»; `"Лапки"` → «"Лапки"»; `Тема &amp; x` → буквально «Тема &amp; x» (як і у видимій назві через esc). Ланцюг esc → innerHTML (розкодовує) → plainText → esc — рівно один шар.
- `$x_1 + \log_2 8 + x_{AB} + a_n$` → «x₁ + log₂8 + xAB + an» (буквені індекси — як раніше).
- `urlAttr`: `javascript:` → `#`, `HTTPS://…?b=1&c=$` → `&amp;`, `%24`; відносний `img/a.png` і `mailto:` → `#`. У змісті 59 note.links і 179 credits — усі `https://`, тож регресії немає (note.links validate і так вимагає https).

## tools-validate-tex-escapes

`jsEscapeIssues` (скан сирого тексту): перевірено на синтетичних рядках і на справжніх файлах.
- Чисто: `\n` перед кирилицею й латинським словом (`"a\nNote"`), `é`, `\u{…}`, `\\Delta`, HTML у `"…"` і `` `…` ``, `//` в URL усередині рядка, блокові й рядкові коментарі, апостроф у коментарі, вкладений `${ "\\frac" }` у шаблоні.
- Ловить: `\Delta`, `\sqrt`, `\cdot` (ковтаються), `\frac`, `\neq`, `\to`, `\vec` (керівні символи); у коментарі — ні.

- Скоуп `--section`: зіпсований g9m2 дає помилку в `--section g9m2` і повному прогоні, але **не** в `--section g8m1` — чужий файл автора не блокує.

## Знахідки P3 (не блокують)
1. **Лексер `STR_LIT` не знає регулярних виразів** (tools/validate.mjs, `jsEscapeIssues`): `const r = /"\d/;` → хибне `\d`; `/a\/*b/` відкриває «коментар» і ховає наступний `"\Delta"`. Також `String.raw` дав би хибне спрацювання. У змісті 0 regex-літералів і 0 String.raw (зміст — дані), тож зараз не шкодить; варто коментар у коді або пропуск `/…/` після `=(,:`.
2. **`\n`/`\t` + рівно TeX-назва** (`"x\ne"`, `"a\to"`) дає помилку, хоча це може бути навмисний перенос. Рідкісно, повідомлення зрозуміле — прийнятно.
3. **Прогалина тесту:** скоуп `--section` для скану сирих файлів не покритий — мутація «завжди сканувати всі файли» (`const only = null`) проходить test-validate (177/177). Поведінка правильна (перевірив вручну вище); бракує фікстури «зіпсований чужий файл не потрапляє в `--section X`».
4. **Вкладені дужки в SVG-індексі** (наявне до змін): `SVG_TOK` не розбирає `x_{a_{bc}}` — голий `_` дає порожнє тіло, і наступна літера отримує dy=-3 (зсув угору). Гілка `reset = r - d` досяжна лише для `x_{a_b}`. У змісті 0 випадків; svgTexIssues цього не позначає.
5. **credits не валідуються**: якщо колись з'явиться не-https URL, `urlAttr` мовчки дасть `href="#"` з `target=_blank` (відкриє копію застосунку). Варто перевірку в validate, як для note.links.
6. Нотатка виконавця: «для пулу склеєний fbText зі steps більше не перевіряється» — неточно: checkScreen його пропускає, але checkTex 1а перевіряє (у `seen` замість fbText null). Шкоди немає.
