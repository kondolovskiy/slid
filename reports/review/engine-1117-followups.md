## Знахідки

### P1-1. Не-цифра в порожній клітинці стирає цифру в попередній (регресія) — app/lab.js:812–816
```js
if (/\d/.test(raw)) return;
if (state[id] >= 0) { setParams({ [id]: -1 }, true); focusDigit(digitNext(last.handles, id, -1)); }
else if (!raw.includes(CELL_NIL)) { const p = digitNext(last.handles, id, -1); if (p) { setParams({ [p]: -1 }, true); focusDigit(p); } }
```
Фокус виділяє вміст клітинки (CELL_NIL), тож будь-який друкований не-цифровий символ замінює заповнювач: `raw` = «,», «.», «-», « », «a» — без CELL_NIL і без цифри, і гілка трактує це як Backspace. Числова клавіатура Android (Gboard) має «,» «.» «-» і пробіл поруч із цифрами.
Відтворення (Playwright, Pixel 7, 360 px, 4572 : 3 з `input: true`, як сценарій 20): у d3 вписати «1» (фокус на d2) → `keyboard.insertText(",")` → стан `-1,-1,-1,-1`, фокус на d3: вписана «1» стерта. Те саме для `press("a")`, `press("Space")`. Над заповненою клітинкою «.» стирає її й переносить фокус назад.
На коді до змін (211375d) той самий зонд: стан `1,-1,-1,-1`, фокус лишається на d2 — нічого не стирається.
Очікувано: «стерти» лише за порожнього `raw` (або за `inputType` `deleteContent*`), не-цифровий символ — ігнорувати (відновити поле, як раніше). Потрібен сценарій у test-ui (не-цифра в порожній і заповненій клітинці не змінює стану), що падає на поточному коді.

### P3-2. Картка плану з багатьма прогалинами — стіна тексту

### P3-3. Обмеження CELL_NIL
Каретка перед заповнювачем (iOS може не виконати `select()` на focus) — Backspace не дасть події; автор це зазначив. На справжньому телефоні не перевірено ні автором, ні мною. Заповнювач не потрапляє в стан/відповідь/збереження: зонд — `localStorage` без U+200B; відповідь береться зі `state`, `aria-valuetext` — з `h.value`, не з поля.
