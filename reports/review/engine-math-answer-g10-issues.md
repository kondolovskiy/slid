## Знахідки

**P1-1. `listPre` приймає як «невідому» будь-яку малу латинську літеру з формул умови: назви функцій, векторів, послідовностей, параметри й іншу змінну.** `taskVars` (app/learn.js, після `parseList`) додає кожну літеру `[a-z]` з `$…$` і виключає лише ліву частину на початку формули чи після `,`/`;`. Тому `f` з `$f(x) = …$`, `b` з `\vec{b}`, `a` з `$a_n = …$` і `x` у задачі «знайди $b$» вважаються дозволеними. Раніше всі ці записи давали `bad`.
Хибні `ok` у реальному контенті (скан: для кожної list-вправи пробую `L = k₁; L = k₂` для L = a…z):

| Вправа | Що питають | Також дає `ok` |
|---|---|---|
| pg8m5:b08 | значення $b$ у $3x^2 - bx + 12 = 0$ | `x = 12; x = -12` |
| pg9m3:a02 | нулі $f(x) = x^2 - x$ | `f = 0; f = 1` (хибне твердження: f(x) ≠ 1 у нулі) |
| pg9m3:a04 | нулі $g(x) = 35 - 2x - x^2$ | `g = …; g = …` |
| pg9m5:a07 | номери $n$ членів $a_n$ | `a = …; a = …` (значення членів інші) |
| pg9m2:d07 | значення $x$, вектори $\vec a$, $\vec b$ | `a = …`, `b = …` |
| pg9m2:c07 | значення $y$, вектор $\vec b$ | `b = 5; b = -5` |

Синтетичні випадки (p1.mjs): система `$x + y = 3$, $x - y = -1$` дає `ok` і для `x = …`, і для `y = …`. Для «ординат точок перетину $y = x^2$ та $x + y = 2$» дає `ok` на `x = 1; x = 2`. Для `$y = kx + b$` дає `ok` на `k = …` і на `b = …`.
Відтворення: `node /tmp/claude-0/-home-user-slid/019b4ace-7221-55df-8577-39871bfa5ec5/scratchpad/probe/p1.mjs`. Для реальних вправ: `checkAns(pg9m3 a02, "f = 0; f = 1")` → `ok` (було `bad`).
Чому тести й diff-answers цього не бачать: test-learn не має негативу на кшталт «назва функції / параметр поруч зі змінною». diff-answers генерує префікси лише `x`, `y`, `t`, `х`. Його категорія «g10 п.2» перевіряє тільки, що старий рушій на записі без префікса дає той самий вердикт. Тому будь-яка прийнята літера, зокрема чужа, вважається «поясненою».
Як виправити (консервативно): знімати префікс лише тоді, коли після виключень лишається **рівно одна** кандидатна літера. Виключати: літеру перед `(` (`f(x)`, `g(t)`), літеру з індексом `_` (`a_n`), аргумент `\vec{…}`/`\overrightarrow{…}` і задані ліві частини. Якщо кандидатів кілька (pg8m5:b08 — `b`, `x`), лишати `bad`, як було. Альтернатива — брати літеру з «значення(ях) $b$» / «знайди $x$». Додати в test-learn негативи з таблиці. У diff-answers генерувати префікс для кожної латинської літери умови і не зараховувати в категорію п.2 зміну `bad → ok`, якщо літера не єдина кандидатна (або виводити такі записи окремим списком для людини).

**P3-1. `(x+5)2` тепер читається як `2(x+5)`, хоча це найчастіше пропущений `^`.** Значення обчислено правильно (зліва направо, як `1/2x`), а записи з ключем `(x+5)^2` дають `bad`, як і раніше. Отже, наявні правильні записи не змінилися. Але учень, який мав на увазі квадрат, при ключі `2(x+5)` отримає `ok`, а при ключі `(x+5)^2` — голе `bad` без підказки. `1/(x+1)2` = `2/(x+1)` — той самий випадок. Пропозиція (не блокує): для ключа без такого запису давати `form`/badHint «Степінь пиши через ^: (x + 5)^2, множник — перед дужками».

**P3-2. Прогалина тестів для intervalSet у validatePool.** Мутація «прибрати `limited` навколо `parseSet` у validatePool (і не задавати BUDGET)» проходить test-learn зеленим: ключі тестів (`√2`, `√3`) не потребують `xmul`. Варто додати ключ intervalSet з межею на кшталт `(1+√5)/2`, яка потребує точного множення, першим у свіжому рушії. Також мутація «індекс префікса `\d+` замість 1–4» не ловиться (`x5 = 2`). Обидві прогалини дрібні.

**P3-3. `limited(…, () => null)` у validatePool.** Якщо ключ занадто важкий (TOO), то для intervalSet перевірка перетину мовчки пропускається, а для exactRoot з'являється хибна причина «потребує кореня або π». Справжню помилку це не маскує, бо такий ключ однаково ловить завершальна перевірка `checkAns(it, keyInput(it)) !== "ok"` (p5.mjs: `(√2+√3+√5)^12` → «не читається…»). Повідомлення варто уточнити.
