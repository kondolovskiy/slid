## (1) answer у діагностиці

- **Вердикт без фідбеку.** `check()` при `run.diag` одразу викликає `diagAnswer(gradeNow(s) ? OK : BAD)` (app.js:1035). Через це немає `showMarks`, fb, hint, formHint чи badHint і немає другої спроби. `gradeNow` для answer дає ok лише при `checkAns === "ok"`, тому form зараховується як BAD.
- **Розмітка.** Під полем показано лише підказку формату. Для time це `timeExample` (≠ ключ), для quantity — список одиниць, для number — `numberHelp` (приклад, який перевірка цієї вправи не зараховує). Регресійний сканер «підказка ≠ ключ» тепер бачить і завдання діагностик. aria-label поля — «Відповідь», у кнопок — «Вставити …». Витоку ключа немає.
- **Обмеження `DIAG_ANSWER_KINDS`** (number | time | quantity) перевіряє `learn.validate`. Перевірено фікстурами: list, expression і coordinates2 у тесті дають помилку.
- **Збережені й перервані тести.** Механізм `rev`/`resumeDiag`/`diagRunRev` не змінено. Тест у плеєрі з фікстурою rev 3 поверх dg6 ред. 2 відкидає вердикт лише заміненого завдання, переживає reload, а результат має `rev 3`.
- **План і known.** `buildPlan`/`finishDiag` працюють лише з вердиктами OK/BAD/SKIP і від типу завдання не залежать. `diagAnswer` у журнал помилок не пише.
- **Офлайн.** Нових файлів немає, список ASSETS не змінився.

## Знахідки

### P3-1. Опція замість ревізії в `--content-old`
`tools/diff-answers.mjs:198–203`: відсікається лише значення на `--`.
- **Відтворення:** `--content-old "-o<шлях>"` → `git archive -o<шлях> app content` створює порожній файл у довільному місці; далі «not a valid object name: app».
- Неіснуюча ревізія закінчується трасою стеку Node (rc 1), а не зрозумілим повідомленням.
- **Що зробити:** перевіряти ревізію через `git rev-parse --verify --end-of-options <rev>^{commit}` і передавати в `git archive` перевірений хеш.
- Інструмент локальний, тож ризик низький.

### P3-2. `objs` надто широкий, коли шукану назву не розпізнано
`app/learn.js:658–661`, `nameLen`.
- Якщо умова називає шукану точку без слова з ASK_WORD («Знайди координати $D$»), лише в заголовку або в реченні без «знайди», її природна назва `D(…)` тепер дає form, хоча раніше давала ok.
- У поточному змісті таких вправ немає (скан і diff-answers), але правило латентне.
- **Що зробити:** додати в test-learn негативний приклад і, за бажання, попередження validate для coordinates-вправ з `ask = null` і непорожнім `objs`, де ключ — точка.

### P3-3. У тесті form зараховується як BAD без пояснення, а формат не завжди видно
Для quantity `form: "compound"` підказка під полем — «Кілька одиниць — через пробіл, спершу більші». Вона не каже, що потрібен саме складений запис, тож «245 см» тихо стає BAD. Так само з `reduced`/`mixed`/`fractionOnly` для number: там загальна підказка. Валідатор не перевіряє, що умова називає формат. Документація (CONTENT_SCHEMA §9) перекладає це на автора.
- **Що зробити:** у тесті явно писати вимогу формату в підказці answerUI або додати попередження validate для діагностичних answer з цими полями. Пов'язано з рішенням людини нижче.

### P3-4. Розбіжність правил і дубль повідомлення
- `learn.validate` дозволяє `signed` для answer будь-якого answerKind, тоді як правило пулу (через answerFieldIssues) — лише для числової answer. Підсумок однаковий (помилка), але повідомлення приходить лише з правила пулу.
- Потрійне «немає title» на цій гілці зникає після злиття з wt-p3c (див. (5)).

### P3-5. Межі `--content-old`
- `loadContent(dir)` бере зі старої ревізії й `app/registry.js`, `lab.js`, `learn.js`, `math.js`. Для сумісності змісту це правильно, але ревізії, у яких ще не було якогось файлу з manifest (наприклад, `app/lab.js`), падають.
- `TEXT_ONLY` вважає `title`/`body` текстом: якщо змінити запитання без зміни ключа, rev не вимагається. Це свідома евристика, її варто згадати в коментарі або документації.
