## Знахідки

### P2-1. Показник кореня перед «√» зливається з попереднім числом-коефіцієнтом
`app/math.js` (command, `sqrt`): `<sup class="root-index" style="order:-1">` + чинний CSS `.root-index{align-self:flex-start;margin:.05em -.15em 0 0}` (index.html р. 335).
Показник стоїть угорі зліва від «√» на висоті звичайного степеня, без відступу зліва. Після цифри він читається як степінь числа:
`2\sqrt[3]{2}` → «2³√2» (схоже на 2³·√2 = 8√2), `5\sqrt[8]{256}` → «5⁸√256», `0,3\sqrt[3]{1000}` → «0,3³√1000».
Реальний зміст: content/math/pool-g10-g10m3.js (8 формул, зокрема саме вправа на винесення множника `\sqrt[3]{16} = 2\sqrt[3]{2}`).
Відтворення: знімок Chromium із CSS index.html (скрипт рецензента rv11/shot.py) — для `0,3\sqrt[3]{1000} - 5\sqrt[8]{256}`.
Пропозиція: опустити показник у «гачок» знака й дати відступ зліва, напр. `.root-index{margin:.45em -.32em 0 .15em}` (перевірено знімком: «0,3 ³√1000», «5 ⁸√256» читаються однозначно; окремі `\sqrt[3]{x^2}`, `(\sqrt[4]{81})^3` теж гаразд). Це CSS у index.html (розробник) або той самий inline-стиль у math.js.
`plainNode` в app.js не зламано: показник лишився всередині `.sqrt`, атрибути «³√x²» (сценарій «Formulas in attributes» зелений).

### P3-1. Підказка «Сталу запиши великою C» там, де C — не стала первісної
`constC` (app/learn.js) спрацьовує для будь-якого ключа з доданком `+ C`: ключ `a + b + C` (умова без латинської c), запис `a + b + c` → `form` «Вираз правильний. Сталу запиши…». Не хибне ok (не зараховано), у змісті таких ключів нема (лише pg11m3 a01–a03). За бажання — обмежити ключами з `C` як окремим доданком при наявності іншої змінної інтегрування або прапорцем вправи.

### P3-2. `√n²` → form і для дослівного переписування умови
Якщо умова «Обчисли √576», переписаний запис `√576` дістає «Значення правильне. Обчисли корінь…». Нової інформації не дає (не підказує відповідь, не зараховує), але фраза «значення правильне» для копії умови дивна. Залишити або не давати form, коли запис дослівно є в умові.

### P3-3. Прогалини тестів (мутації виживають)
Власні мутації (14) на app/learn.js проти test-learn.mjs: ловляться 10. Виживають:
- видалення двійника `"М": "M"` чи `"Т": "T"` з CYR_TWIN — немає тесту на ці літери (лише х, у, с, к, А…);
- `!ka.includes("c") &&` у constC — майже еквівалентна (ключ з c і C не стане тотожним після заміни c→C);
- `B === 0n ||` у mixedNum — еквівалентна (`A >= B` уже відкидає 0 у знаменнику).
Додати тест на кожну велику літеру-двійник (принаймні М, Т, Н, В) у виразі чи координатах.

### P3-4. diff-answers: тонке покриття двох категорій
п.3 (мішане число) і п.5 (0,(3) у межі) дають по 1 запису на весь зміст 4–11 кл. — генератор бере лише ключі з неправильним дробом-доданком / межею з періодичним дробом. Не ховає небажаного (категорії вимагають, щоб старий рушій на «очищеному» записі давав той самий вердикт), але реальне покриття — в test-learn. Категорія п.1 (646) перевіряє `new(v) == old(lat(v))` і запис без іншої кирилиці — коректна умова; п.4 (629) вимагає саме `form` + текст «Обчисли корінь» і точний цілий корінь — `ok` туди не потрапив би (0 непояснених).
