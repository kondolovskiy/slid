### (1) Зміна `save()` у `app/app.js:144`

```js
const save = () => { try { localStorage.setItem(KEY, JSON.stringify(S)); } catch(e) { try { localStorage.removeItem("slid.evidence.pending"); localStorage.setItem(KEY, JSON.stringify(S)); } catch(e) {} } EV.observe(S); };
```

- **У звичайних умовах поведінка та сама.** Якщо `setItem` вдається, виконується той самий один запис того самого JSON. Резервна гілка спрацьовує лише тоді, коли запис кинув виняток. Вміст і порядок `slid.v1` не змінюються. Це підтверджують `diff-answers`, regression-сюїта (порівняння `slid.v1` з журналом, без IndexedDB і без модуля) і `--content-old`.
- **Чужих ключів не видаляє.** Видаляється лише буквальний ключ `slid.evidence.pending`. Інших ключів localStorage застосунок не має: `grep` по `app/*.js` знаходить лише `slid.v1` і цей ключ.
- **Без модуля журналу все коректно.** Видалення відсутнього ключа нічого не робить, повторний запис іде як звичайно. Якщо localStorage кидає SecurityError, обидві спроби потрапляють у `catch`, як і раніше.
- Ім'я ключа записано буквально, бо без модуля `_core.PENDING` недоступний. Розбіжність імен зламала б резерв, але браузерний тест її спіймає: він заповнює сховище через `_core.PENDING` і чекає, що `slid.v1` збережено.

### (2) «105 непояснених» у `diff-answers --old 53833ea` — артефакт інструмента (T-1)

Ця зміна `app/learn.js` не зачіпає: `git diff 53833ea d113b3d -- app/learn.js` порожній. Тому вердикти змінитися не можуть.

Відтворення: `node tools/diff-answers.mjs --old HEAD --grades 4-11`, тобто старий і новий learn.js однакові. Вивід: «Вердикт тесту рівня (diagAnswerOk → diagVerdict), записів 39769: 1623 half корінь…, **105 НЕПОЯСНЕНІ**», rc 1. Основний блок дає 0 непояснених.

Причина:
- `tools/diff-answers.mjs:326` вмикає блок, щойно в старому learn.js є `diagAnswerOk`.
- `:341` порівнює `OLD.diagAnswerOk(s,v) ? "OK" : "BAD"` з `V[NEW.diagVerdict(s,v)]`.
- Але після engine-diag-half-credit (`01acba8`) `diagAnswerOk = (s, v) => diagVerdict(s, v) === OK` (`app/learn.js:1271`). Тому будь-який HALF на старій стороні стає «BAD», і кожен HALF виглядає як зміна «BAD → HALF».
- Частину таких записів блок «пояснює» як «корінь не обчислено» (1623), решта 105 стають «непоясненими». Це, наприклад, `pg4m4:d09 «3250 кг»` і `pms1:e01 «2,25»` при `2 1/4`, де HALF дає вимаганий вигляд.

**T-1 (P2, інструмент; цю задачу не блокує).** Будь-яка ревізія після half-credit, передана як `--old`, дає хибне rc 1 і сотні хибних «змін». Це штатна перевірка кожної інженерної задачі, тож справжні зміни тонуть у хибних, а «0 непояснених» перестає бути критерієм. Виправлення: якщо `typeof OLD.diagVerdict === "function"`, порівнювати `V[OLD.diagVerdict]` з `V[NEW.diagVerdict]`, а `diagAnswerOk` брати лише для ревізій до half-credit (`tools/diff-answers.mjs:326,341`). Плюс регресійний тест: `--old HEAD` дає 0 змін у блоці тесту рівня. Пропоную окрему задачу `engine-diff-answers-half-old`.
