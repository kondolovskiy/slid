# Пастки й як їх обійти

## Контент і код
- **`${` у зворотних лапках.** У шаблонному рядку `` `$${x}` `` JavaScript підставить змінну і «з'їсть» формулу. Приклад з першої сесії: синтаксис дробу `{3|4}` у `` `…$…$` `` перетворювався на `7` (`3|4`). Тому дроби пишемо `3/4`, а валідатор ловить `${` у тексті.
- **`(…)` усередині формули** стає групою для дробу, а текст «ост.» склеюється без пробілів. Для тексту всередині формули — лапки: `$$17 : 5 = 3 "(ост. 2)"$$`.
- ~~**Поле `number` приймає лише цифри.** Десяткові дроби чи від'ємні відповіді — через `choice` (або новий тип рушія; пропозиція в inbox).~~ Застаріло з D-014 (2026-10-05); виправлено 2026-10-11.
- **Поле `number` приймає кому й від'ємні числа.** Кома — завжди; кнопка «±» з'являється, якщо `answer` від'ємне, з 7 класу — завжди, або з `signed: true` у розділі чи на екрані (CONTENT_SCHEMA §2, §4). У розділі з від'ємними числами став `signed: true` на весь розділ: інакше сама поява «±» видає знак відповіді (verifier-g6m4).
- **id уроків і навичок — ключі прогресу.** Перейменування «губить» прогрес дітей. Лише нові id.
- **Порядок розділів** визначає `grade`, потім `weeks[0]`. Якщо тижні однакові (алгебра й геометрія), порядок — як у файлі плану.
- **fbText показується і при правильній, і при неправильній відповіді.** Не пиши «Ти помилився, бо…».
- **`order.shuffle`** не може бути тотожним порядком (валідатор ловить), інакше завдання вже розв'язане.

## Зображення й артефакт
- **CSP артефакту Claude блокує зовнішні зображення, стилі й fetch.** Усе — локальними файлами поруч (`files` під час публікації).
- **Хмарна сесія Claude не має доступу до wikimedia** (проксі відхиляє). Обхід: вбудований браузер на комп'ютері користувача → `upload.wikimedia.org` (same-origin fetch) → canvas → завантажити файл → перенести в проєкт. Кілька завантажень одним викликом браузер блокує — по одному. Файли інколи потрапляють у «Завантаження» під тимчасовими прихованими іменами `.Q6L2SF6YDW...`; розпізнавати за розміром зображення (`file`).
- `thumb.wikimedia.org` віддає мініатюри з іншого домену, ніж `upload`; простіше брати оригінал з `upload` і зменшувати самому.

## Тестування
- **Плейтест** через Playwright з `/opt/pw-browsers/chromium` у хмарі; локально — `playwright install chromium`.
- **Playwright локально — у `.venv-playtest/`** в корені проєкту (у .gitignore), не в тимчасовій теці сесії: систему чистить /tmp, і пакети зникають. Запуск: `./.venv-playtest/bin/python tools/playtest.py --section <id>` (orchestrator, 2026-10-11).
- **Плейтест не запускати паралельно з іншим плейтестом** — обидва піднімають сервер на одному порту. Лише оркестратор, по черзі (2026-10-11).
- Google Fonts у хмарному контейнері не вантажаться — плейтест блокує їх, це не помилка.
- Після кожного уроку в плейтесті натисни «Навчання» двічі (скидання навігації на головний екран).

## Процес
- Агенти, що паралельно запускають `tools/build.mjs`, переписують `index.html` одне одному. Збирає лише оркестратор наприкінці.
- Автор, що сам себе перевіряє, пропускає свої ж помилки. Верифікатор — інший агент, свіжий контекст.
- **Спільний scratchpad сесії.** Паралельні агенти пишуть тимчасові файли в одну теку й затирають одне одного (`c1.jpg`, `enum.mjs` — траплялося двічі, 5 і 11 жовтня). Кожен агент працює лише у власній підтеці `scratchpad/<задача або id розділу>/`.
- **Жодних персональних даних у мережевих запитах** (docs/IMAGES.md). 2026-10-07 агент передав email власника в User-Agent запиту до Wikimedia. User-Agent — нейтральний, без імен, пошти, шляхів з іменем користувача.

## Зображення: Вікісховище (додано 2026-10-11)
- **Commons API віддає 429 «too many requests»** при паралельних авторах. Завантажуй по одному файлу з паузою 8+ с.
- **`extmetadata.LicenseShortName` для фото творів мистецтва** (шаблон Art Photo) може показувати ліцензію самого твору («Public domain»), а не фото (напр. CC BY-SA 3.0). Дивись wikitext сторінки файлу (`action=raw`), поле photo license (writer-g7s3).
- **Файл без опису й джерела не бери** навіть з «правильною» назвою: `File:Trypillia_P1010113.JPG` — не доказ, що це трипільська кераміка (verifier-g6s2). Походження предмета звіряй з описом: фото «трипільського» горщика з Neues Museum виявилося з Кукутені (Румунія).
- **Зображення в `credits`, але не на жодному екрані** валідатор не ловить (`img/hist/g7s1/olga.jpg`). Перевіряй сам: кожен файл з теки розділу має бути використаний.

## Лабораторія (`lab`, `explore`) — авторські пастки (додано 2026-10-11)
- **Мета — умова, а не одна точка.** «Зафарбуй третину» з вільним n: `3*k==n`, а не `n==3 && k==1` — інакше 2 з 6 відхиляється (verifier-g4m5).
- **`show` не має рахувати те, що питають** у оцінюваному `lab` (напр. `{abs(a)}` у завданні на модуль). Живий рядок на кшталт «AC = BC? так» має збігатися з `goal` і у вироджених станах; `max(0, …)` у `show` може показувати «0» там, де мета не виконана.
- **Повзунок показує своє число** — у завданнях «постав точку на числі» дитина підганяє цифри, не читаючи шкалу. Став `out: false` на параметрі (або `values: false` на моделі).
- **numline:** точки обрізаються до `view`, стрибки — ні; `view` має покривати максимум виразу на всьому діапазоні повзунка. Два ряди стрибків з метою «зійдуться в одній точці»: пиши «зупини обох там, де…», а не «додавай, доки не збіжаться» — слід збігається й тоді, коли один ряд перескочив точку (verifier-g6m1).
- **plane:** якщо (y1−y0)/(x1−x0)·320 < 160, поле отримує H = 160 і клітинки неквадратні. Для «1 клітинка = 1 см» тримай співвідношення сторін `view` не вужчим за 1:2 або задай `h`. Рухома точка на межі `view` видна наполовину — лишай запас у `view`.
- **plane + кути на цілій сітці:** `goal` виду `angle(…)==N` майже недосяжний поза 45°/90°/135° (і кути з √3). Краще: `angle(A)==angle(B)`, сума 180, або допуск / дрібніший snap (g7m2, g7m4, g7m6, g7m8 — 11.10).
- **params з `min==max`** валідатор відхиляє (фіксований k). Обхід — константа в y-виразі, не вироджений параметр (g7m5).
- **`drag: true` на точці з x/y-виразом** (напр. `"2+t"`) не рухає параметр — лише чисте імʼя параметра. Для зсуву — повзунок або `x: "t"` (g8m6).
- **`\sqrt{x}` у `show`/`label` lab** парситься як шаблон `{x}`. Пиши Unicode `√` або екрануй (g8m3, g10m1, g10m3). Показник $a^{m/n}$ у `show` — `a^(m/n)` у дужках: `{…}` після `^` не atom у mathHTML (g10m3).
- **`\vec{a}` / `\overrightarrow{AB}` у lab `show`/`label`** ламають шаблони (`{a}`, `{AB}`). У show писати «a→» / «AB→» (g9m2).
- **Пропущена кома після `body` / template literal** у файлі розділу ламає `loadContent` для *наступних* скриптів у маніфесті (validate чужого `--section` падає). Після синтаксичної правки — `node tools/build.mjs` (g8s3 → g9m7; g10m4 `cta`, 12.10).
- **Вкладені лапки в `"…"`** (`$"рад"$`, `\\"arcsin"`) ламають рядок JS і весь `loadContent`. Пиши template literal `` `…` `` або конкатенацію `" + "arcsin" + "` (g10m5, паралельний g10m6).
- **`lab` plane: параметр не може зватися `x`** (конфлікт із координатою). Інше імʼя; `d(f,a)` ок для дотичної (g10m6).
- **balance** з вагою-параметром x і метою-тотожністю: терези пишуть «рівновага» й за інших наборів для окремих x. Мінімальна вага x має бути більшою за найбільшу можливу різницю гир; перевіряй перебором станів («рівновага» ⟺ мета). Якщо модель знімає гирі повзунком — питай x через `number` з `lab`, а не роби метою крайнє положення повзунка.
- **rect не має перетягуваних маркерів** — не пиши «тягни кут», лише «рухай повзунок».
- **chart:** `max` під крайній стан дає стовпчики 9–13 px у розв'язку — добирай `max` під стан розв'язку. Число з розрядів будуй виразом (`{r4*10000+…|0}`), а не склеюванням `{r4|0}{r3|0}`.
- **Варіанти `choice` рушій не перемішує** — міняй позицію правильного сам (D-016). Те саме для зайвого варіанта в `multi` і для «правильної» здогадки в `hyp`.
- **Переліки чисел у тексті** рахуються як слова й роздувають `maxReadWords` / `sentenceWords` — довгі списки (дільники) лишай у `fbText`.
