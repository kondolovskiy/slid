# Процес: від плану до уроку в застосунку

```
plan.js ──make-tasks──▶ tasks/todo ──claim──▶ doing ──автор──▶ review ──верифікатор──▶ done
                                                   │                    │
                                                   ▼                    ▼
                                             inbox.md ◀──── факти, пропозиції
                                                   │
                                        куратор пам'яті (/handoff)
                                                   ▼
                              memory/long (facts, glossary, decisions, pitfalls)
                                                   │
                         style-sync ◀── stats.mjs ─┘ (профілі складності)
                                                   ▼
                                    учитель: status "approved"
```

## 1. План
`content/<предмет>/plan.js` — розділи з назвою, «навіщо», тижнями й темами. Змінює куратор (після звірки з програмою НУШ).

## 2. Задачі
`node tools/make-tasks.mjs` створює `tasks/todo/write-<предмет>-<id>.md` для кожного розділу без уроків.
Інші типи задач створюють вручну або агенти: `verify-*` (перевірка), `style-*` (виправлення стилю), `img-*` (зображення), `eng-*` (зміни рушія).

## 3. Паралельний запуск (оркестратор)
1. Оберіть пакет: **один предмет і один клас** (напр. історія 6 кл., 5 розділів). Так автори бачать одні й ті самі еталони і пишуть однаково.
2. `node tools/claim.mjs claim <task> <agent>` для кожного; запустіть авторів паралельно (у Claude Code — `/parallel 5 hist 6`).
3. Після всіх: `npm run check` і `python3 tools/playtest.py` (у Claude Code — субагент `qa-runner`, дешева модель; плейтест бере вільний порт, можна паралельно).
4. Верифікатори — **окремим запуском**, свіжий контекст, по одному на розділ.
5. `/sync-style <предмет>`, потім `/handoff`.

## 4. Як синхронізується стиль і складність

Уроки одного предмета, написані різними агентами в різний час, мають звучати як один автор. Для цього п'ять рівнів:

| Рівень | Механізм | Де |
|---|---|---|
| Правила | стиль-гайд предмета: голос, будова уроку, типові формулювання, приклади «так / не так» | `style/common.md`, `style/<предмет>.md` |
| Еталони | 1–2 розділи-зразки на предмет і діапазон класів; автор копіює структуру | `style/<предмет>.md` → «Еталони» |
| Словник | терміни, нотація, написання імен і дат — одна форма на весь предмет | `memory/long/glossary/<предмет>.md` |
| Факти | одне формулювання й дата для кожного факту | `memory/long/facts/<предмет>.md` |
| Метрики | кількість екранів, частка завдань, слів на екран, слів у реченні, частка довгих слів, різноманітність завдань — порівняння з профілем і з «сім'єю» (той самий предмет і діапазон класів, z-оцінка ≥ 2 → прапорець) | `style/profiles.json`, `tools/stats.mjs`, `reports/style-*.md` |

Style-sync запускається після кожного пакета. Якщо урок випадає, спершу виправляють урок. Профіль змінюють, лише якщо випадає більшість нових уроків і це обґрунтовано (рішення записують у `decisions.md`).

**Складність між класами** росте плавно: профілі задано для діапазонів 4 / 5–6 / 7–9 / 10–11 (довші речення, більше термінів, більше тексту на екран у старших класах). Для 7+ класів профілі поки екстрапольовані: після перших 10 уроків цих класів перекалібруйте їх за фактичними даними.

## 5. Статуси й відповідальність
- `draft` — написав автор, пройшов валідатор.
- `verified` — ШІ-верифікатор звірив факти й відповіді; звіт у `reports/verify/`.
- `approved` — учитель-предметник прочитав і схвалив. **Лише людина.**
Для публікації дітям — лише `approved` (зараз у прототипі показується все, зі стікером «чернетка»).

## 6. Що перевіряти вручну (людині)
- Відповідність модельній програмі й календарному плану конкретної школи.
- Чутливі теми (Друга світова, Голодомор, війна з 2014 р.).
- Чи зрозуміло це дитині цього віку: дайте урок 3–5 дітям.
