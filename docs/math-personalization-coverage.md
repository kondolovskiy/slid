## Межі діагностики

Діагностика вимірює опори, пул тренує кожен required-урок. Pre має дві проби; cur — одну репрезентативну, а не річну контрольну. У таблицях нижче `A → B` — точний `item.lesson` базової й складнішої проби (повтор того самого id дозволено). У `lessons` — унікальні 1–2 id. `for` вказує розділ; дужки дають конкретний цільовий урок, у якому опору застосовують. Це не нові `requires` рушія. Вигаданих lesson id немає.

Cur відноситься лише до названого уроку. Одна перевірка обчислення не доводить володіння всіма темами розділу; перед авторством треба зіставити ядро уроку з пробою. Для нових cur конкретне ядро кожного уроку перелічено в probes/coverageObjectives: один multi/sort перевіряє всі ці компоненти. Якщо достатню пробу не вдається скласти, автор повертає вибір уроку/проби куратору до зміни матриці; самовільного прапорця «не ставити known» у чинному контракті немає. Поточний рушій `known` відкриває урок, а не засвідчує опанування; не розширювати цей ефект на решту розділу.

Завдання цих таблиць — навчальні цілі для авторів, **не готові умови/ключі**. У нових тестах базові проби перед складнішими, теми перемішуються, cur — у другій половині. DIAG_TYPES чинні; нові формати answer пулу не можна переносити в діагностику без підтримки. Для точної відповіді коренем/множиною в тесті використовувати choice/multi/lab, якщо вільне введення ще не підтримано.

**Час 10–15 хв — гіпотеза**, не вимірювання. Максимуми рахують екрани до адаптивного скорочення; складений multi/sort може містити кілька компонентів, їхню кількість теж треба фіксувати в пілоті; фактичну кількість показаних проб і час читання/розв’язання фіксує research-math-diag-duration, окремо за класами.

## Вимоги до baseline 4 класу

Вісім опор 1–3 класів: place, add, sub, mul, quot, ord, units, parts. Їх підтримує повторення за 3 кл. у Гісь 4 ч.1 с.7–36 і Логачевської 4 ч.1 pdf-с.4–24. Проби мають бути в межах трицифрових чисел, табличних добутків/часток і знайомих одиниць; не підміняти їх новим матеріалом 4 класу.

У JSON `baseline: true`, порожні lessons та null у itemLessons — **проєкт даних для engine-math-diag-g4-baseline**, не вже дозволений контракт SLID.diag. Інтегратор визначає мінімальне розширення схеми; автор dg4 чекає на нього. Не вигадувати уроки 1–3, не підміняти pre на cur.

Рівень має враховувати виміряні baseline-opори; усе пропущено не може дати «Міцну базу». Показати конкретну прогалину навіть без уроку повторення, рекомендацію попрактикувати вміння з учителем/дорослим і доступний перший required-урок відповідного розділу 4 класу. Кнопка за відсутності кроків повторення веде до навчання 4 класу, не до порожнього плану. Такий перехід не закриває прогалину автоматично. Результат baseline лишається до повторної діагностики/окремо визначеного вимірювання.

## Повний реєстр уроків і пулів

`pre` нижче — змістові опори, а не нові вимоги блокування в app. Для першого уроку 4 кл. точні опори без id беруться з baseline відповідного розділу. `diag` показує cur, який вимірює сам урок; «—» означає, що окремої cur-проби для цього уроку немає. Перелік preForSection у JSON задає вимірювані опори розділу. Решту уроків усе одно покриває пул. Межі ядра — short/learned чинного уроку плюс зазначені виключення, не всі задачі відповідного параграфа підручника.

`number` = чинне числове введення, зокрема десяткові, звичайні й мішані дроби. ratio/coordinates2/coordinates3/exactRoot/intervalSet/expression/periodicSet — **вимоги до формату**, не затверджені назви answerKind; контракт реалізує engine-math-pool-answer-formats. Список можливих форматів не означає, що кожна вправа має вимагати всі формати. choice/multi — для нечислового висновку, не обхід перевірки числової відповіді.

Нових загальних sk не потрібно: послідовності/логарифми — expr/func, просторові координати — coord. Автори не додають альтернатив divis/prop. Матриця рекомендує основний sk вправи; наявні sk уроків інших класів не переписує заднім числом.

Особливо: гілки коренів квадратного рівняння (list), знак і порядок координат, відкриті/закриті межі проміжків, π та параметр k∈Z у тригонометричних відповідях. Не зводити точний об’єкт до округленого числа/однієї компоненти зі зміною мети. Відкладені coordinates3/площина потрібні лише при майбутній інтеграції optional/pending.

engine-math-grade-plan-context має залишати валідні required-опори молодших класів і повертати до поточного класу після тренування; ключовий шлях dg6 → ms2l4 → pms2 збережено. Матриця не дає права автоматично відкривати optional/pending. Спільний QA перевіряє фактичний required-набір із JSON, а 13 відкладених уроків звітує окремо. Технічні тести не доводять математичної правильності й часу учня.

## Виправлення після незалежної перевірки v1 → v2

- dg8 tri-angles: замість зовнішнього кута — висновок про можливість трикутника за двома кутами, який пояснено у g7m4l3.
- dg9 polygon: число сторін за сумою кутів, без непоясненого поняття правильного многокутника.
- dg10 root/func: корені добутку/частки повних квадратів та явно область значень; не вимагати непоясненого винесення множника чи D(f).
- dg10 area: площа прямокутника → ms4l1; єдине застосування for — оптимізація площі g10m6l4, без недоведених площ у g10m2/g10m4.
- Для кожної нової cur визначено всі компоненти ядра coverageObjectives і один multi/sort, що їх перевіряє; незалежна перевірка готового тесту обов’язкова. У поняттєвих рядках явно дозволено choice/multi поряд із числовими вправами.

Обсяг, сталі id й поточний dg6/pg6 не змінено. V1 залишається історичною версією в коміті 1b7a5ea; нове авторство й QA посилаються на v2.
