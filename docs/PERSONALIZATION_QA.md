# Перевірка персоналізації

Інструменти працюють на частковому наборі контенту. Матриця `docs/math-personalization-coverage.json` визначає required-уроки, пули, формати й кількості; optional/pending мають окремі списки. Поточна версія — 2026-10-16.v2: 50 розділів / 182 тематичні уроки, 169 required / 48 пулів, 7 optional / 6 pending, 8 діагностик.

```bash
# Без браузера й залежностей: інвентар, посилання, джерела, навички, рівні, покриття
node tools/personalization-qa.mjs
node tools/personalization-qa.mjs --grade 6
node tools/personalization-qa.mjs --diag dg6
node tools/personalization-qa.mjs --pool pg6m2 --json

# Суворе приймання всього required-пакета або одного класу
node tools/personalization-qa.mjs --strict
node tools/personalization-qa.mjs --grade 6 --strict

# Браузер: потрібні Playwright та Chromium
python3 -m pip install playwright
python3 -m playwright install chromium
python3 tools/test-answer-ui.py --grade 6
python3 tools/test-answer-ui.py --suite content --diag dg6
python3 tools/test-answer-ui.py --suite content --pool pg6m2
python3 tools/test-answer-ui.py --suite regression
python3 tools/test-answer-ui.py --strict

# Уже встановлений Chrome можна обрати без завантаження Chromium
python3 tools/test-answer-ui.py --browser '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' --grade 6

# Самоперевірка QA-інструмента та чистої логіки рушія; входять у check/CI
node tools/test-personalization-qa.mjs
node tools/test-learn.mjs
```

`--grade`, `--diag`, `--pool` обмежують реальний контент. `--diag` і `--pool` взаємовиключні; клас можна поєднати з одним із них. Невідомий аргумент/id, порожній перетин, відсутні доступні об’єкти та непідтриманий драйвер відповіді завершують команду помилкою. `--suite regression` запускає контрольовані fixtures і не приймає фільтрів контенту. Типово `all` запускає реальний набір та fixtures; `content` — лише реальні об’єкти. Браузер друкує кількість діагностик, пулів і справді перевірених вправ.

Звичайний режим блокує структурні помилки доступного контенту, але дозволяє незавершений пакет і повідомляє прогалини. `--strict` додатково блокує відсутній required-контент, незавершену незалежну верифікацію, відсутні рівні/формати/навичку з матриці та непідтримані сценарії. Повний суворий режим зараз **має падати**. Це окремо від успішного технічного прогону чинних dg6/pg6. Винятки кількості беруться з `exercises.min/max` і пояснення рядка матриці; три рівні потрібні для кожного required-уроку. Навичка рядка має бути представлена, додаткові оголошені навички дозволено.

Для діагностик звіряються також `itemSkills` і `itemLessons` у порядку проб кожної теми. Неявна прив’язка до єдиного уроку теми еквівалентна явному `item.lesson`; для теми з двома уроками пропущена прив’язка не проходить strict. Індекси проб `itemIndices` звіряються там, де їх зафіксовано в матриці (зокрема для збережених відповідей dg6).

У тесті діагностики виконуються всі правильні відповіді, справжня базова помилка з пропуском складнішої, shaky та «Ще не знаю». Кожен сценарій перевіряє «Пізніше», збереження/відновлення після першої відповіді та початок повторного тесту. До завершення тесту фідбек, підказки, лічильники-відповіді, зміни XP/комбо/навичок/журналу помилок заборонені. Наявні 20 XP за завершення тесту — окрема чинна поведінка рушія.

Кожна реальна вправа пулу проходить звичайний екран і перевірку відповіді; перевіряються `seen`, кроки, джерело, недоступність тем до уроку й доступність після запису пройденого уроку. Для повного обходу пул тимчасово обмежується порціями до шести вправ у пам’яті браузера. Запис пройдених уроків тут — fixture; повне проходження справжнього ms2l4 уже є в сценарії міжкласового контексту. Реальний пул 5 класу залишається для фінального приймання після його авторства.

Після кожної порції перевіряються SRS, збереження й завантаження офлайн через справжній service worker, потім відкривається тренування без мережі. Сервер має вільний локальний порт. Час календаря зафіксовано на 16.10.2026 для нових контентних і сесійних сценаріїв. Fixtures сесії перевіряють 4 + 2 з двох тем повторення, пріоритет небачених над помилковими/успішними, hint і другу спробу, перехід повторюваних помилок у план, малий/вичерпаний/порожній пул, зростання й скидання SRS. Решта граничних випадків пріоритетів і дат — `test-learn.mjs`.

Драйвер повторює порядок уроків застосунку при однакових датах SRS; окрема браузерна регресія містить два уроки у зворотному порядку з різними відповідями. Автори пулів можуть вільно перемішувати вправи різних уроків у файлі.

Додавання класу не потребує нового раннера: зареєструвати diag/pool і запустити `--grade N`. Для нового типу екрана розширити `answer_context_screen`; невідомий тип викликає помилку. Для реальної базової помилки наразі драйвер підтримує number/choice на першій pre-темі; новий тип потребує явного доповнення. Контракт baseline 4 класу підтримано (engine-math-diag-g4-baseline): аудит звіряє `baseline` теми з матрицею, `test-answer-ui` має регресію fixture dg4 (усе правильно / усе пропущено / змішано: рівень, `plan.base`, перехід до наявного уроку, прогалина не закривається уроком), `playtest` для тесту лише з baseline-передумовами вимагає `plan.base` з уроком замість кроків. Реальний dg4 перевіряється тими самими `--grade 4` / `--diag dg4` після його авторства. Символьні формати (ratio, coordinates2/3, exactRoot, intervalSet, expression, periodicSet; list із коренями) мають регресію в цьому самому файлі: fixture-пул проводить кожен формат через справжній екран — перша спроба з неправильним або неспрощеним записом (підказка «form»), друга з еквівалентним записом іншого вигляду; вставка кнопкою в місце курсора, «k ∈ ℤ» біля поля й показ ключа після двох помилок. Модульні випадки еквівалентних і неправильних записів — у `test-learn.mjs`. Аудит вважає формат матриці присутнім, якщо `answerKind` вправи має ту саму назву; драйвер реальних пулів вводить ключ як записано (масив `ratio` — через « : »).

Введення `answer` з файла перевіряє технічне зарахування відповіді. Математичну правильність, відповідність джерелам, повноту методів і педагогічну опору перевіряє незалежний верифікатор. Інструмент перевіряє структуру URL/посилання на джерело; доступність і зміст URL він не засвідчує.
