# Схема контенту

Увесь навчальний зміст — JavaScript-файли в `content/`, які викликають функції реєстру з `app/registry.js`.
Нічого не треба компілювати: браузер підвантажує файли по черзі (список у `index.html` оновлює `tools/build.mjs`).

## 1. Предмет — `content/subjects/<id>.js`

```js
SLID.subject({
  id: "hist", subject: "Історія України", diagOrder: 3, short: "Історія", icon: "pot", pattern: "spiral",   // pattern: spiral | grid | none
  colors: { light: { accent: "#A8431F", soft: "#F3E3DA", mid: "#D98E6E", ink: "#FFFFFF" },
            dark:  { accent: "#E0764E", soft: "#3A2419", mid: "#8A4A33", ink: "#1A1310" } },
  skills: { src: { name: "Джерела", hint: "Розрізняти види джерел…" } },   // навички для екрана «Прогрес»
  badges: [ { id: "hstar", name: "Зіркова історія", icon: "star", desc: "…", allstar: true } ]
});
```
`diagOrder` (необов'язково, число): після вибору класу відкривається тест рівня предмета з найменшим `diagOrder` (зараз math 1, ukr 2, hist 3, world 4); предмет без нього — після всіх предметів із `diagOrder`; за рівних і серед предметів без поля — порядок предметів у збірці. На головній — одне запрошення на новий тест у тому самому порядку (docs/PERSONALIZATION.md §1). Кольори генерують CSS автоматично. `allstar: true` — значок за 3 зірки в усіх уроках предмета в поточному класі.

## 2. Розділ — `content/<предмет>/g<клас>-<id>.js`

```js
SLID.section("math", {
  id: "ms1",               // унікальний на весь застосунок; для розділу з плану — той самий id, що в plan.js
  grade: 5,                // клас; від нього залежить фільтр у застосунку
  weeks: [16, 21],         // тижні навчального року (1–35) для картки «Зараз у школі»
  title: "Звичайні дроби",
  why: "Щоб чесно ділити піцу…",       // «Навіщо» — показується дитині
  requires: ["m4a"],       // необов'язково: уроки-передумови (чип «Спирається на»)
  signed: true,            // необов'язково: кнопка «±» в усіх числових полях розділу (з 7 класу вона є завжди) — щоб її поява не видавала знак відповіді
  plan: ["…"],             // необов'язково: переходить із plan.js автоматично
  meta: { author: "writer-<задача>", created: "2026-09-27", factcheck: "self", teacher: null },   // author — роль агента чи людина, не назва моделі ШІ (AGENTS.md §5; інакше попередження validate)
  badges: [ { id: "mboss", name: "Кондитер", icon: "trophy", desc: "…" } ],   // значки, що видаються уроками розділу
  credits: [ ["Назва фото", "Автор", "Ліцензія", "https://commons.wikimedia.org/wiki/File:…"] ],
  lessons: [ /* уроки */ ]
});
```
Розділ **без** `lessons` — плановий (лише в `plan.js`): показується з темами й позначкою «уроки готуються».

## 3. Урок

```js
{
  id: "m1",                 // унікальний на весь застосунок (зберігається в прогресі дитини — не перейменовувати!)
  title: "Що таке дріб?", short: "Частини цілого", icon: "pizza",   // icon — ключ з const P у app/app.js
  status: "draft",          // draft → verified (ШІ-верифікатор) → approved (учитель)
  boss: true,               // необов'язково: фінальний урок, бали ×2
  badge: "mboss",           // необов'язково: значок за проходження (оголошений у sec.badges або subject.badges)
  why: "…",                 // показується в картці уроку
  screens: [ /* екрани */ ],
  outro: { text: "…", learned: ["…", "…"], pollKey: "l1", pollText: ["…"] }   // pollKey/pollText — якщо в уроці є опитування
}
```

## 4. Екрани

Спільні поля: `type`, `eyebrow` (надзаголовок), `title`, `body` (HTML), `sk` (ключ навички), ілюстрація — одне з:
`img` + `cap` (+ `tall` для вертикальних фото на чорному тлі або `fit` на білому), `svg` (назва SVG-ілюстрації з `svgFig()` в app.js), `fig` (математична фігура, див. §6),
`lab` (інтерактивна модель, див. §8 — можна й на `choice`/`number`: дитина експериментує, перш ніж відповісти).

Примітка під текстом екрана (будь-який тип) — `note`: згорнутий рядок «Чому дві дати?», що розгортається по натиску (D-022). Рядок HTML або `{ text, label?, links? }`; `label` — інший заголовок замість «Чому дві дати?», `links` — `[["Назва джерела", "https://…"], …]`. Примітка не оцінюється й не може бути опорою для завдання — лише пояснення, чому джерела розходяться.
```js
note: { text: "<p>Літопис називає 945 р., але …</p>", links: [["Ігор — Енциклопедія історії України", "https://…"]] }
```

Для завдань: `fbOk` (заголовок при правильній), `fbBad` (заголовок при помилці), `fbText` (пояснення **чому** — показується завжди), `hint` (підказка після першої помилки), `pre` (id уроку-передумови: при помилці дитині запропонують його повторити).

Механіка завдань: перша помилка → підказка й друга спроба; друга помилка → показ правильної відповіді. Друга спроба зараховується лише після зміни відповіді: доки відповідь та сама, що й у першій спробі, кнопка неактивна, а Enter нічого не перевіряє. Після перевірки фокус переходить на «Далі», тож Enter веде на наступний екран. Поки плеєр відкрито, фон неактивний (`inert`), і Tab не виходить за межі плеєра. 10 балів з першої спроби, 5 з другої; серія з 3, 5, 7… правильних — бонус.

| type | Поля | Що робить дитина |
|---|---|---|
| `intro` | `cta` | читає проблему, з якої починається урок |
| `info` | `cta` | читає теорію (після проблеми!) |
| `choice` | `opts[]`, `correct` (індекс) | обирає один варіант |
| `choice` + `poll: "key"` | `opts`, `fbTitle`, `fbText` | опитування без правильної відповіді; вибір згадується в `outro` |
| `choice` + `hyp: true` | `opts`, `fbTitle`, `fbText` | висуває гіпотезу; усі відповіді приймаються |
| `multi` | `opts[]`, `correct[]` | обирає кілька. Варіанти підписано літерами А, Б, В… (український алфавіт без Ґ, Є, Ї, Й, Ь — 28 літер, `OPT_LETTERS` в app/app.js); більше варіантів, ніж літер, — помилка validate |
| `sort` | `bins[]`, `items: [[текст, індекс кошика], …]` | розкладає по кошиках. Рядки плеєр показує в перемішаному порядку (`LANG.rowOrder`, раз на показ екрана), тож порядок `items` нічого не підказує; у поясненнях не посилайся на «перший», «останній» рядок |
| `order` | `items[]` (у правильному порядку), `shuffle[]` (порядок показу — перестановка індексів) | торкається в правильній послідовності |
| `slider` | `min`, `max`, `step`, `start`, `answer`, `tol` (частка), `unit` | оцінює число; зараховується в межах ±tol |
| `align` | `ref: {from, to, seed}`, `sample: {len, endYear}` | суміщає візерунок кілець дерева з еталоном |
| `shade` | `shape: "bar"|"circle"`, `n`, `target` | зафарбовує частини фігури |
| `numline` | `den`, `max`, `answer` (у поділках) | ставить точку на координатному промені |
| `number` | `answer` (число), `unit`, `tol` (допустима похибка, необов'язково), `signed` | вводить число; поле завжди приймає кому; якщо `answer` від'ємне (або `signed: true`) — з'являється кнопка «±» |
| `explore` | `lab` | досліджує інтерактивну модель (без оцінки), див. §8 |
| `lab` | `lab`, `goal`, `solution`, `reveal` | змінює модель, щоб виконати умову `goal`; оцінюється, див. §8 |
| `fracin` | `expr`, `den`, `answer` | вписує чисельник у дріб: `expr = ?/den` |
| `answer` | `answer` (число або рядок: `"7/12"`, `"2 1/3"`, `"-3,5"`), `unit`, `reduced`, `mixed` | сама записує відповідь: ціле, десятковий дріб, звичайний дріб `7/12` або мішане число `2 1/3`. Порівнюється значення; `reduced: true` — дріб має бути скорочений, `mixed: true` — неправильний дріб треба записати мішаним числом (інакше підказка «значення правильне, але…»). Під полем — кнопки «−», «/», «пробіл» |

Приклад завдання:
```js
{ type: "choice", sk: "cmp", eyebrow: "Порівняй", title: "$3/8$ … $3/5$",
  body: "<p>Який знак поставити?</p>", opts: ["&lt;", "&gt;", "="], correct: 0,
  hint: "Чисельники однакові. Де шматки більші?",
  fbOk: "Молодець.", fbBad: "Згадай правило 2.",
  fbText: "Чисельники однакові, але восьмі частини менші за п'яті. Отже, $3/8 < 3/5$." }
```

### 4.1. Мовні вправи (`app/lang.js`)

Для української мови (і будь-якого мовного предмета). Розмітку розбирає `app/lang.js` — той самий код у плеєрі, валідаторі (`tools/validate.mjs`) і тестах (`tools/test-lang.mjs`). Поля фідбеку (`fbOk`, `fbText`, `hint`…) — як в інших завданнях. Механіка двох спроб та сама: після першої помилки червоним позначено лише те, що обрано неправильно (правильно обране — зеленим), після другої — показано правильну відповідь. Позначка не лише кольором: екранний диктор чує «… — правильно / неправильно».

| type | Поля | Що робить дитина |
|---|---|---|
| `gaps` | `text` — рядок (можна HTML) з пропусками `{*е\|и}`: варіанти через `\|`, правильний позначено `*`, 2–5 варіантів, ≤ 12 пропусків | у кожному пропуску обирає літеру, буквосполучення чи слово. `—` (довге тире) у розмітці — варіант «нічого не писати» (м'який знак, апостроф, подвоєння, кома): `ден{ь\|*—}ки`; дитина бачить «∅» і легенду «∅ — нічого не писати». Справжнє **тире** як варіант пиши коротким `–` (U+2013): `{*–\|:\|,}` — дитина бачить «—» |
| `pick` | `text` — **простий текст без HTML**; правильні слова — у `[дужках]`; група в дужках `[буде читати]` — одна кнопка; `[!кілька слів]` — **хибна** група-кнопка (`[!слово]` — хибна кнопка з одного слова; пробіли біля `!` і в дужках дозволені: `[ ! слово ]`; `[!!…]` — помилка). Хибних груп з кількох слів має бути щонайменше половина від правильних (на 3 правильні — 2 хибні), інакше форма кнопки видає відповідь (валідатор попереджає) | торкається потрібних слів у реченні (підмет, присудок, однорідні члени, слова з орфограмою). Кожне слово — кнопка, розділові знаки — ні; ≤ 40 слів |
| `stress` | `words: ["черг+овий", "вип+адок"]` — 1–6 слів, `+` перед наголошеним голосним | торкається голосного, на який падає наголос, у кожному слові. Односкладові слова не дозволені |
| `word` | `answer` — рядок або масив допустимих записів; `before` / `after` — текст біля поля; `keys: ["'", "-"]` — кнопки, що вставляють символ; `keepCase: true` — зважати на велику літеру | вписує слово чи форму. Порівняння без урахування регістру, апостроф `' ’ ʼ` і дефіси `- – —` однакові, знак наголосу ігнорується. Якщо відповідь кирилична, латинські літери-двійники (`i a e o c p x y k` і великі) зараховуються як кириличні — навіть коли все слово чи сполучник «і» набрано латиницею |
| `split` | `word: "мо\|ло\|ко"` або масив допустимих поділів того самого слова (`["ли\|сти\|на", "лис\|ти\|на"]`); `zero: true` — після слова клітинка нульового закінчення «□», межа перед нею — `|` у кінці: `word: "стіл\|", zero: true` | ставить межі між літерами: склади, перенос, будова слова (`при\|мор\|ськ\|ий`). Показ відповіді — «мо-ло-ко»; у слові з дефісом межі — «\|» (`жов\|то-бла\|кит\|ний`), з `zero` — «стіл-□». Межу можна поставити й біля апострофа чи дефіса — врахуй це у варіантах |

```js
{ type: "gaps", sk: "orth", title: "Е чи И?", text: "Ми йшли с{*е|и}лом, а з{е|*и}ма вже минала.",
  hint: "Зміни слово так, щоб на голосний упав наголос.", fbOk: "Так.",
  fbText: "Село — с<b>е</b>ла, зима — з<b>и</b>ми: ненаголошений звук перевіряємо наголошеним." }
{ type: "pick", sk: "synt", title: "Знайди граматичну основу", text: "[Сонце] яскраво [світить] над полем.", fbOk: "Точно.", fbText: "…" }
{ type: "stress", sk: "oral", title: "Де наголос?", words: ["черг+овий"], fbOk: "Так.", fbText: "Черго́вий — наголос на о." }
```
Наголос у тексті уроку (не в `stress`) позначай знаком U+0301 після голосного: `черго́вий`.

Варіанти пропуску `gaps` плеєр показує в перемішаному порядку (раз на показ екрана; «∅» — завжди останнім), тож порядок у розмітці нічого не підказує — правильний можна писати де завгодно, а в поясненнях не посилайся на позицію кнопки.

На вузькому екрані (телефон, 360–375 px) варіанти пропуску переносяться в кілька рядків усередині пропуску, а варіант з кількох слів — між словами; слово з пропуском (разом із літерами й розділовим знаком поруч) не розривається. Тож довгі варіанти (фрази, цілі речення) допустимі — за край картки вони не виходять (engine-gaps-wrap; перевіряє `tools/test-ui.mjs`, сценарій 14). Обмеження: пропуск з довгими варіантами плеєр робить вужчим за картку лише на 2em — це місце для літер і розділових знаків, приклеєних до пропуску без пробілу (`«{…}».`, `{…}!`). Не приклеюй до такого пропуску більше ~2em тексту (2–3 літери чи знаки): постав пробіл або перебудуй речення, інакше рядок вийде за край. Суцільне слово, ширше за картку, переноситься всередині кнопки варіанта.

Обмеження (валідатор): у `stress.words` і `split.word` — **без** U+0301 та інших комбінованих знаків (наголос у `stress` — лише `+`); у `word.answer` і словах `pick` не змішуй кирилицю з латиницею; у `pick` і `split` — без HTML; у `split.word` — жодного пробілу чи невидимого символу (U+200B, м'який перенос U+00AD), і на краю слова (`" мо|ло|ко"` — помилка: плеєр зробив би з пробілу клітинку для межі).

Попередження валідатора: у `gaps` не розривай слово з пропуском HTML-тегом (`<b>б{…}р</b>{…}за` може перенестися посеред слова) — обгорни тегом усе слово (`<b>б{…}р{…}за</b>`) або винеси тег за його межі; теги всередині `<span class="gw">…</span>` (nowrap, як обгортка плеєра: транскрипція `<span class="gw">[ди́ви<sup>е</sup>{…}а]</span>`) не розривають рядок — попередження немає; варіант `—` з пробілами довкола (` — `) чи поруч із варіантами, що містять тире (`, —`), найімовірніше мав бути тире `–`.

**Здогадка (`hyp: true`)** на мовних типах дозволена: дитина обирає, плеєр нічого не позначає й не зараховує, показує `fbTitle` (обов'язково) і `fbText` — там і назви правильну відповідь. Розмітка та сама, що й для оцінюваного завдання (у `gaps` — теж `*`). **`poll`** — лише для `choice` (стан мовної вправи не зберігається для `pollKey` в outro).

Заборонені фрази (style/banned-phrases.txt) не рахуються в `<s>…</s>` (закреслене — помилка, яку урок виправляє), у коротких «лапках» до 4 слів (згадка слова чи кальки: «Приймати участь» — калька; довша пряма мова в лапках перевіряється), у неправильних варіантах `gaps`, `choice` і `multi` (варіанти опитування `poll` перевіряються), в усіх варіантах здогадки `hyp` і в `[дужках]` `pick` («Знайди помилку»: `[вірно]`, `[!на протязі]`). Якщо варіанти пропуску `gaps` відрізняються лише регістром (`{*вітаю|Вітаю}`), а `fbText` пише слово лише так, як хибний варіант (виділене `<b>` — будь-де; інакше не на початку речення, не після «:» і не після «слово…/пишемо…»), — попередження: «*», мабуть, не на тому варіанті. У поясненнях (`fbText`, `fbBad`, `fbOk`, `hint`) не посилайся на номер варіанта («у другому варіанті», «варіант Б») — назви сам варіант. Для предмета `ukr` валідатор попереджає про милозвучність у/в, і/й, з/із/зі (УП § 23–25) за правилами з малим шумом; повний звіт з усіма правилами — `node tools/euphony.mjs [--subject ukr]` → `reports/euphony-ukr.md` (курсив і «лапки» — приклади й цитати — не перевіряються; «зі» перед числівником — «зі дві години» — не позначається); звіт охоплює уроки, пули й тести рівня предмета; `--section ID`, `--pool ID` чи `--diag ID` друкує звіт одного розділу, пулу чи тесту в stdout і спільний файл не перезаписує (`--exercises` — варіанти й речення вправ; пропуск `gaps`, варіанти якого не містять у/в/і/й/з/із/зі, там стає правильним варіантом, тож прийменник поруч перевіряється: `{*при́клад|прикла́д} з байки`). «З» усередині речення перед одиничним з, с, ц, ж, ч, ш («виготовлено з золота» → «із золота», УП § 25 п. 2) і між приголосними («приклад з байки» → «із байки») — лише у звіті. «Й» після слова на й, я, ю, є, ї («моя й твоя» → «моя і твоя», УП § 24 п. 4) — лише у звіті, не у validate: частку «й» («допускає й інші») механічно не відрізнити від сполучника, тож кожну знахідку перевір; виділене `<b>` це правило перевіряє, як і решта.

## 5. Формули

У будь-якому тексті: `$…$` — у рядку, `$$…$$` — окремим рядком по центру. Усередині:

| Пишеш | Бачить дитина |
|---|---|
| `3/4` | дріб стовпчиком |
| `2~3/4` | мішане число 2¾ |
| `(a + b)/c` | чисельник з кількох знаків |
| `*` | множення · |
| `:` | ділення : (як у школі, а не ÷ чи /) |
| `-` | мінус − |
| `a`, `x` | змінні курсивом |
| `"(ост. 2)"` | звичайний текст усередині формули |
| `x^2`, `(x-1)^2`, `2^(n-1)` | степінь (верхній індекс) |
| `0{,}6` | десяткова кома, як `0,6` (TeX-запис, підтримується) |
| `\\lg 100`, `\\log_2 8`, `\\ln x` | назва функції прямим шрифтом, перед аргументом без дужок — тонкий пробіл: «lg 100» (так само пишуть і `\\text{lg}\\,`) |
| `\\sqrt[3]{x^2}` | корінь з показником перед знаком: ³√x² |
| `1 \\to 4` | стрілка з відступами, як «=» (також `\\rightarrow`, `\\leftrightarrow`) |

⚠️ У рядках у зворотних лапках (`` `…` ``) не пиши `${` — JavaScript сприйме це як вставку. `$1/5$` безпечно, а от `$${`… — ні. Валідатор це ловить.

⚠️ Поза `$…$` TeX не рендериться: `$1 \\to 4$,\\; $2 \\to 5$` покаже дитині «,\;». Пробіл між формулами — звичайний пробіл. Формули не рендеряться й в атрибутах: `cap` (стає `alt` фото), `lab.alt`, назва уроку (aria-label кнопки на мапі) — там пиши простим текстом (√2, x₁). Валідатор: TeX поза формулою, непарний `$` у будь-якому тексті екрана (і в `items`, `pairs`, `steps`), назва уроку з `$` чи TeX, `cap`/`lab.alt` з формулою — помилка.

⚠️ У звичайних лапках `"…"` бекслеш TeX-команди подвоюй: `"$|\\Delta x|$"`. З одним `\` JavaScript ковтає його (`"\Delta"` → «Delta», `"\overrightarrow"` → «overrightarrow») або читає як керівний символ (`"\frac"` → `\f` + «rac», `"\neq"` → перенос рядка + «eq»). Валідатор сканує сирий текст файлів і дає помилку з номером рядка.

⚠️ Назви функцій у формулі — `"sin"`, `"tg"`, `"log"` у лапках (або `\\sin`, `\\cos`, `\\log`, `\\ln` — вони є в app/math.js). Без лапок `$sin x$` покажеться курсивним добутком s·i·n. Валідатор попереджає (поза `"…"`, `\text{…}` і шаблонами `{…}`).

Нова фігура чи SVG-ілюстрація — це зміна рушія (`mathFig()` / `svgFig()` в app.js): запропонуй у inbox.

**Рисунок, якого вимагає умова (tools-math-fig-audit).** Якщо умова посилається на рисунок («на рисунку», «за малюнком», «на кресленні», «за графіком», «на діаграмі», «зображено на», «рис. 2»), на тому самому екрані має бути ілюстрація (`fig`, `img`, `svg` або `lab`) — інакше validate попереджає «умова посилається на рисунок…» (в уроці не попереджає, якщо ілюстрація є на попередньому екрані; про сюжетний вступ `intro` не попереджає — його fig-audit показує окремою групою). Не посилання: розклад («за графіком руху автобусів», «графіком чергувань / уроків / занять / прийому»), «на передньому плані»; «за графіком руху велосипедиста», «графіком зміни температури» — посилання. «на плані», «на схемі» — лише кандидати fig-audit (часто сюжет; у ukr «схема» — схема речення, у звіт не йде). Геометрія з позначеннями, яких немає на екрані, — теж привід для рисунка. Геометричні креслення — статичний `lab` (`kind: "plane", axes: false, grid: 0`, без `params`; тіла — `solid`; діаграми — `chart`). Рисунок точно відповідає умові (позначення, пропорції, дані) і не підказує відповіді: шукане не підписуй, дугу кута без числа давай з `label: false` (інакше lab друкує виміряні градуси). Перелік кандидатів — `node tools/fig-audit.mjs` → reports/fig-audit-math.md (евристики, є хибні збіги).

## 8. Лабораторія: інтерактивні моделі (`lab`)

Як у Brilliant: дитина **тягне повзунки або точки** й одразу бачить, як змінюється графік, фігура, числова пряма чи терези.
Рушій — `app/lab.js`; валідатор сам перевіряє вирази, мету й розв'язок.

Три способи використати:
- `type: "explore"` — модель для дослідження без оцінки («Пограйся з k. Що відбувається з прямою?»). Далі — `choice` з висновком.
- `type: "lab"` — завдання: «Зроби так, щоб…». Поля `goal` (умова-вираз), `solution` (значення параметрів, що її виконують — для показу відповіді й плейтесту), `reveal` (необов'язково: текст під моделлю, коли показано відповідь).
- `lab` на звичайному завданні (`choice`, `number`) — модель як жива ілюстрація до питання.

### 8.1. Параметри, вирази, шаблони
```js
lab: { kind: "plane",
  params: { k: { min: -3, max: 3, step: 0.5, start: 1, label: "$k$" }, b: { min: -4, max: 4, start: 0 } },  // повзунки; step за замовчуванням 1
  // межі можуть залежати від інших параметрів: k: { min: 0, max: "n", start: 1 } — не більше, ніж частин
  // out: false — не показувати число біля повзунка (коли дитина має прочитати шкалу сама); values: false — для всіх повзунків моделі
  let: { s: "k*2+b" },                       // похідні величини (необов'язково)
  fns: [{ id: "f", y: "k*x+b" }],            // функції від x; з id їх можна викликати: f(2)
  points: { M: { x: "2", y: "f(2)" }, P: { at: [1, 1], drag: true } },
  show: "$y = {k; b|poly}$"                  // рядок(и) під моделлю з живими значеннями
}
```
- **Вирази** — рядки: `+ - * / ^`, дужки, неявне множення (`2x`, `3(x+1)`), порівняння `== != < > <= >=`, `&& || !`. Десятковий знак у виразах — **крапка** (`0.5`); дитина бачить кому.
  Функції: `sqrt abs sin cos tan` (радіани), `sind cosd tand` (градуси), `ln lg log(b,x) exp root(n,x) min max round(x,d) floor ceil mod fact C(n,k) A(n,k)`,
  геометрія `dist(A,B) angle(A,B,C)` (градуси, кут при B) `area(A,B,C,…) slope(A,B) X(P) Y(P) pt(x,y)`, аналіз `d(f,a)` (похідна), `integ(f,a,b)`, `mean(…)`. Сталі `pi`, `e`.
  `==` порівнює з допуском 10⁻⁶. Ім'я `x` у `plane` зарезервоване. Кілька літер поспіль — одне ім'я (`kx` ≠ `k*x`).
- **Шаблони** (`show`, `label` тощо): `{вираз}` — число (до 2 знаків), `{вираз|0}` — ціле, `{вираз|c}` — коефіцієнт (1 → «», −1 → «−»),
  `{вираз|s}` — доданок зі знаком («+ 3», «− 2», 0 → «»), `{вираз|deg}` — градуси, `{вираз|pi}` — частки π, `{год|time}` — «14:30», `{хв|hm}` — «2 год 15 хв», `{a; b; c|poly}` — многочлен `ax² + bx + c` з правильними знаками.
  ⚠️ Шаблони пиши у звичайних лапках `"…"`, не у зворотних (`` `${k}` `` JavaScript «з'їсть»).
  ⚠️ `$` у шаблоні — лише парами навколо формули: `"Сторона {s|0}"` або `"$s = {s|0}$"`, а не `"Сторона ${s|0}"` (лишиться «Сторона $4»). `{,}` у шаблоні — десяткова кома, а не вставка.
- **Формули в підписах SVG** (`points.label`, `segs`/`fns`/`angles`/`jumps`/`items`/`bars` `.label`, `texts.t`, `aLabel`, `splitLabels`…): малюється безпечна підмножина — літери курсивом, числа, `; , = + − · < >`, індекси з одного знака `x_1`, `a^2` (`{…}` у підписі — шаблон: `a^{n}` підставить значення n), пробіли `\\,` `\\;` і символи `\\Delta \\alpha \\pi \\cdot \\times \\pm \\le \\ge \\ne \\to \\angle \\circ \\infty…` (повний список — `SVG_SYM` в app/lab.js). `\\sqrt`, `\\frac` тощо в підписі — помилка валідатора (пиши `√`, `a/b`). Дужки всередині індексу чи степеня (`x_{a_{b}}`) теж помилка; у підписах-шаблонах це перевіряється після підстановки, тож `x^{2{,}5}`, `a^{{n}}` — чисто, а в `xname`/`yname`/`bars`/`marks` (без шаблонів) `x^{2{,}5}` — помилка. `show` і підписи повзунків рендерить app/math.js — там уся підтримувана нотація.
- **Перетягування:** точка з `drag: true` і `x`/`y`, що є іменами параметрів, рухає ці параметри (`{ x: "a", y: "f(a)", drag: true }` — точка ковзає графіком).
  Якщо жодна з координат не є параметром (`{ x: "2+t", y: "4", drag: true }`), точку не рухає ні миша, ні клавіатура: validate попереджає, а в Tab вона не потрапляє — прибери `drag` або зроби координату параметром.
  Клавіатура (рушій, без полів у змісті): Tab до ручки, стрілки — на крок параметра, Home/End — до меж (x), PageUp/PageDown — великий крок (y; на числовій прямій — x).
  Скорочення `{ at: [5, 4], drag: true }` створює приховані параметри `Ax`, `Ay` (крок `snap` моделі або `step` точки, за замовчуванням 1). У `solution` вказуй саме їх: `{ Ax: 1, Ay: 5 }`.
- **Мета** `goal` — вираз, що стає істинним, коли завдання виконано: `"f(2)==3"`, `"angle(B,O,A)==90"`, `"a*b==12 && a!=b"`. Валідатор перевіряє: на старті мета **не** виконана, `solution` досяжне повзунками й виконує мету.
  Якщо правильних відповідей кілька — пиши умову, а не конкретні значення (`"a*b==12"`, а не `"a==4 && b==3"`).

```js
  body: "<p>Змінюй $k$ і $b$, доки пряма не пройде через $M(2; 3)$.</p>",
  lab: { kind: "plane", params: { k: { min: -3, max: 3, step: 0.5, start: 0 }, b: { min: -4, max: 4, start: 0 } },
         fns: [{ id: "f", y: "k*x+b" }], points: { M: { x: "2", y: "3", color: "red", coords: true } }, show: "$y = {k; b|poly}$" },
  goal: "f(2)==3", solution: { k: 1, b: 1 },
  hint: "Підстав $x = 2$: має вийти $2k + b = 3$.",
  fbOk: "Пряма проходить через M.", fbText: "Точка лежить на графіку, якщо її координати задовольняють рівняння: $2k + b = 3$. Підходить, наприклад, $k = 1$, $b = 1$ або $k = 2$, $b = -1$." }
```

## 9. Діагностика класу (`SLID.diag`) — `content/<предмет>/diag-g<клас>.js`

Короткий тест після вибору класу. Він не ставить оцінок: шукає прогалини в темах попередніх класів і з'ясовує,
що з поточного класу дитина вже вміє. З результату рушій складає персональний план (docs/PERSONALIZATION.md).

```js
SLID.diag("math", {
  id: "dg6",                 // унікальний на весь застосунок; ключ у прогресі дитини — не перейменовувати
  grade: 6,                  // для якого класу тест
  title: "Що ти вже вмієш?",
  why: "Знайдемо теми, які варто згадати, щоб нові уроки давалися легше.",   // показується дитині
  status: "draft",           // draft → verified → approved, як в уроку
  meta: { author: "…", created: "2026-10-13", factcheck: "self", teacher: null },
  topics: [
    { id: "frac-cmp", title: "Порівняння дробів", kind: "pre", lessons: ["m2"], for: ["g6m2"] },
    { id: "g6-gcd",   title: "НСД і НСК",          kind: "cur", lessons: ["g6m1l4"] }
  ],
  items: [
    { topic: "frac-cmp", type: "choice", sk: "cmp", title: "Який дріб більший?", body: "<p>…</p>", opts: ["$3/8$", "$5/8$"], correct: 1 },
    { topic: "frac-cmp", type: "number", sk: "cmp", title: "…", answer: 3 }
  ]
});
```

**Тема (`topics`)**
- `id` — унікальний у межах тесту; `title` — назва для дитини («Порівняння дробів», а не «frac-cmp»).
- `kind: "pre"` — передумова з попередніх класів. Помилка → уроки з `lessons` потрапляють у план як кроки на повторення.
- `kind: "cur"` — тема поточного класу. Правильна відповідь → уроки з `lessons` позначаються «знайоме» й відкриваються без черги. Помилка нічого не означає: цього ще не вчили.
- `lessons` — 1–2 id наявних уроків, які закривають саме цю тему (для `pre` — уроки молодших класів, для `cur` — поточного). Що вужча тема, то точніша рекомендація.
- `for` — необов'язково, лише для `pre`: id розділів поточного класу, які спираються на цю тему. Прогалини, потрібні для найближчого розділу, стають у плані першими.
- `baseline: true` — необов'язково, лише для `pre`, коли в застосунку **немає уроків молодших класів** цього предмета (зараз — математика 4 класу: опори 1–3 класів). Тоді `lessons` порожній або відсутній, `for` обов'язковий, а в завданнях теми немає `lesson`. Валідатор забороняє `baseline`, щойно в предмета з'являється хоч один урок класу нижче за тест: тоді треба посилатися на ці уроки. Вигадані id уроків і заміна `pre` на `cur` заборонені. Кожен розділ у `for` — з того самого предмета й класу і має хоч один урок (без boss), інакше валідатор повідомить «нікуди вести». Слабка baseline-тема йде в `plan.base = [{ topic, why, next }]` (docs/PERSONALIZATION.md, «Baseline»); плани, збережені до злиття з полем `l` замість `next`, читаються як `next ?? l`.

```js
{ id: "place", title: "Розряди до тисячі", kind: "pre", baseline: true, lessons: [], for: ["g4m1", "g4m2"] }
```

**Завдання (`items`)** — звичайні екрани-завдання (§4) з полем `topic`. Порядок у масиві = порядок показу.
- Типи: `choice`, `multi`, `sort`, `order`, `number`, `fracin`, `shade`, `numline`, `lab`, `answer` і мовні вправи `gaps`, `pick`, `stress`, `word`, `split` (§4.1; engine-diag-lang-types). Не можна: `slider`, `align`, `poll`, `hyp`, `intro`/`info`.
- **Мовні вправи в тесті:** вердикт той самий `SLID_LANG.check`, що в уроці, — правильно все або ні (часткового зарахування немає); після відповіді нічого не позначається й правильна відповідь не показується. Одне завдання — одне вміння, тож межі (помилка validate): `gaps` — не більше 3 пропусків, `stress` — 3 слів, `pick` — 20 слів-кнопок і 3 правильних; `split` — одне слово (масив — лише варіанти поділу того самого слова). Приклад: `{ topic: "orth-root", type: "gaps", sk: "orth", title: "Встав букву", text: "с{*е|и}ло, з{е|*и}ма" }`.
- Поля фідбеку (`fbOk`, `fbText`, `fbBad`, `hint`) у тесті — попередження: дитина їх не бачить.
- `answer` у тесті (engine-diag-answer-kinds) — лише з `answerKind` `number` (типово; з `decimals`, `form: "improper"`, `fractionOnly`, `reduced`, `mixed`, `signed`), `time` або `quantity` (з `units`, `form: "compound"`); поля й ключ — за тими самими правилами, що в уроці й пулі (§10). Інші формати (вирази, множини, координати, list…) — ні: у них багато вердиктів `form`, які в уроці пояснюють. Вердикт — `SLID_LEARN.diagVerdict` (engine-diag-half-credit, рішення людини 2026-11-01): `ok` — **правильно**; `form` через інший запис того самого, якого умова не вимагала («37» при `decimals: 1`, «0,75» при `fractionOnly`), — **правильно**; `form` через поле, що вимагає вигляд (`reduced`, `mixed`, `form: "improper"`, `compound`), або незавершене обчислення кореня (`√576`, `2√144` при ключі 24) — **півбала** (HALF = 0,5) і короткий екран-пояснення з текстом `formHint`, без другої спроби — і для дослівної копії виразу з умови (`√576` при «Обчисли $\sqrt{576}$»; рішення людини 2026-11-01); `bad` — **неправильно**. Для OK і BAD фідбеку немає. Тема з півбалом — щонайбільше «хитко» (docs/PERSONALIZATION.md). **Вимаганий вигляд умова мусить назвати** — інакше помилка `validate --diag` (дитина не вгадує, якого запису від неї чекають): `reduced` — «скороти» / «нескоротним дробом»; `mixed` — «мішаним числом» / «виділи цілу частину»; `form: "improper"` — «неправильним дробом»; `compound` — «складеним…» або щонайменше дві одиниці вправи («у метрах і сантиметрах», «в м і см»). Для `decimals` і `fractionOnly` без названого формату — попередження: у тесті ця вимога нічого не перевіряє. Формат запису однаково має бути видно з умови й підказки під полем (приклад часу, одиниці величини). Замінити наявне завдання на `answer` можна лише на місці з `rev` (нижче).
- Потрібні `title`, поля типу й `sk`. **Не потрібні** `hint`, `fbOk`, `fbBad`, `fbText`: під час тесту дитина не бачить, правильно чи ні (щоб не вгадувала й не хвилювалась), а підсумок — наприкінці.
- На кожну тему `pre` — рівно 2 завдання: перше базове (одна дія, «чи знає взагалі»), друге складніше (застосування, типова помилка як дистрактор). На тему `cur` — 1 завдання.
- **Адаптивність:** якщо базове завдання теми не розв'язано, складніше не показується. Тому завдання однієї теми йдуть від простішого до складнішого (не обов'язково підряд — теми можна чергувати).
- Підсумок теми `pre`: обидва правильно — «засвоєно»; базове правильно, складніше ні — «хитко»; базове неправильно або «ще не знаю» — «прогалина».
- Baseline-тема рахується в рівні так само (усе пропущено — «Почнемо з основ», не «Міцна база»), але кроком плану не стає: прогалина показується з порадою потренувати вміння з учителем або дорослим і з переходом до першого уроку найближчого розділу з `for` (docs/PERSONALIZATION.md, «Baseline»).
- `lesson` — необов'язково, для тем із двома уроками: який саме урок перевіряє це завдання. Якщо тема «хитка», у план піде лише урок завдання, де була помилка, а не обидва.
- У числових полях тесту кнопка «±» є завжди (знак відповіді не підказується). Назви тем (`topics.title`) — простий текст, без формул.
- `signed: false` на тесті вимикає загальну кнопку «±»; за замовчуванням вона є для всіх числових завдань. Прапорець екрана `signed` і від'ємна відповідь можуть її ввімкнути.
- Лічильники `shade`/`numline` під час діагностики приховано автоматично; в уроці `hideCount: true` приховує числовий підпис, залишаючи рисунок і керування.
- `fracin` з `hideDen: true` не показує готового знаменника: дитина вводить цілий звичайний дріб через `/`. Поля `answer` (чисельник) і `den` лишаються ключем; інструкція має просити весь дріб, а не лише чисельник.
- У дитини завжди є кнопка «Ще не знаю» — вона рахується як неправильна відповідь без жодного покарання.
- **Тема `cur` і known.** Правильна відповідь відкриває урок як «знайоме», тож одне завдання має перевіряти **все** ядро цього уроку (його `learned`): якщо вмінь кілька — складений `multi` (твердження на кожне вміння) або `sort` (вирази на кожну дію) на одному екрані. Одне обчислення не доводить решти вмінь уроку (refine-math-diag-g6-coverage).
- `rev` — необов'язково, ціле ≥ 2: **заміна завдання на місці** в уже опублікованому тесті. Відповіді зберігаються вердиктами за індексом завдання, тому змінювати зміст (тип, ключ, варіанти, суть питання) можна лише так: той самий індекс і та сама тема, нове завдання з `rev: N` (N — номер нової редакції тесту, на 1 більший за найбільший чинний `rev`; без `rev` — редакція 1). Розпочатий у старій редакції тест при продовженні відкидає вердикти завдань, новіших за неї, і показує їх знову; решта відповідей і порядок не змінюються. Завершений результат не перераховується до повторного тесту (`SLID_LEARN.resumeDiag`, docs/PERSONALIZATION.md). Додати, вилучити чи переставити завдання так не можна — потрібен новий `id` тесту. Виправлення друкарської помилки без зміни суті — без `rev`.
- Правило чесного завдання (D-019) тут інше: тест саме й питає те, що було в попередніх класах. Але завдання має перевіряти **одну** тему, а не три одразу, і не залежати від начитаності чи уважності до дрібниць умови.

Перевірка: `node tools/validate.mjs --diag dg6`. Уроки й розділи в `lessons`/`for` — лише свого предмета.

## 10. Пул задач для тренування (`SLID.pool`) — `content/<предмет>/pool-g<клас>-<розділ>.js`

Задачі для самостійної практики після уроку (docs/PERSONALIZATION.md §3). Дитина **записує відповідь**, а не обирає з варіантів.
Задачі теми відкриваються, коли урок пройдено. У сесії — 6 задач: 4 з обраної теми і 2 на повторення раніше пройдених.

```js
SLID.pool("math", {
  id: "pg6m2",               // унікальний на весь застосунок; разом з id задачі — ключ у прогресі, не перейменовувати
  section: "g6m2",           // розділ, уроки якого тренуємо
  also: ["ms0b"],            // необов'язково: розділи, куди перенесено частину уроків пулу (урок переїхав в інший клас — пул і id вправ не ділимо, правило 11); клас вправи в тренуванні — за розділом її уроку. Дизайн: docs/design/math-ister.md §4
  status: "draft",           // draft → verified → approved
  meta: { author: "…", created: "2026-10-13", factcheck: "self", teacher: null },
  sources: [                 // звідки взято задачі: підручник, збірник, офіційні матеріали
    { id: "mer6", title: "Мерзляк А. Г., Полонський В. Б., Якір М. С. Математика. 6 клас. — Харків: Гімназія, 2023", url: "https://…" }
  ],
  items: [
    { id: "a01", lesson: "g6m2l4", lvl: 1, sk: "ops", src: "mer6 №312(1)",
      type: "answer", title: "$1/4 + 1/6$", body: "<p>Знайди суму. Відповідь скороти.</p>",
      answer: "5/12", reduced: true,
      hint: "Найменший спільний знаменник 4 і 6 — це 12.",
      steps: ["НСК(4; 6) = 12.", "$1/4 = 3/12$, $1/6 = 2/12$.", "$3/12 + 2/12 = 5/12$."] }
  ]
});
```

- `id` задачі — короткий, унікальний у пулі. `lesson` — урок цього розділу (не boss), після якого задача відкривається.
- `sk` — навичка, яку тренує саме ця задача; зазвичай одна з `sk` екранів її уроку. Інший `sk` — лише коли задача справді тренує суміжну навичку (personalization-qa попереджає), а не заради збігу з матрицею (docs/PERSONALIZATION_QA.md, «Навички»). Те саме для `sk` завдань діагностики (§9) щодо уроку завдання.
- `lvl`: 1 — одна дія за правилом уроку; 2 — дві-три дії або нестандартні числа; 3 — текстова задача чи завдання з підступом.
- `type`: `answer` (основний), `choice`/`multi` — лише коли відповідь не число («ділиться чи ні»). Числова відповідь — завжди `answer`.
- `src` — «<id джерела> <номер вправи / сторінка>». **Задачі беруться з реальних джерел, а не вигадуються.** Обчислювальні вправи — як у джерелі. Умову текстової задачі переказуй своїми словами, зберігаючи числа й запитання (без дослівного копіювання абзаців підручника).
- `steps` — розв'язання кроками (2–5 коротких рядків, можна з формулами). Дитина бачить його після відповіді; пізніше за ним ШІ перевірятиме хід розв'язання (tasks/todo/engine-ai-solution-check.md).
- `hint` — необов'язково: підказка після першої помилки. `unit` — одиниця біля поля («см²», «грн»). `fbOk`, `fbText` не потрібні.
- **Одиниця в полі.** Якщо в задачі є `unit` (і `unitForms`), дитина може дописати ту саму одиницю після числа — і після кожного елемента `list`: `7 см`, `7см`, `60 грн`, `60 грн.` (крапка після одиниці; у полі вона стає комою — `60 грн,` теж), `8 %`, `70°; 110°`, `70º` (порядковий знак «º» замість «°»), `2√3 см`, `12 см2` / `12 см^2` для «см²», `3 яблук` за `unitForms`, `5 разів` / `3 рази` для unit «раз» (і з прийменником перед числом: `у 2 рази`, `в 3 рази` — engine-math-ister-p3 п. 2; у `list` — перед кожним елементом: `у 2 рази; у 3 рази` = `2; 3`, engine-list-quadratic, TQ-067; без одиниці `у 2`, `у 2; у 3` — ні) — зараховується так само, як без неї (`SLID_LEARN.stripUnit`). Одиниця знімається лише після цифри, `)` чи π і перед `;`, переносом, комою без цифри за нею або кінцем запису; у `coordinates2/3` і `ratio` — ще перед `)` і `:` (`(30°; 60°)`, `30° : 60°`). Чужа одиниця (`7 мм` при «см», `5 км` при «м», `7 см²` при «см») не зараховується; якщо без чужої одиниці число правильне, дитина бачить «Перевір одиницю: тут відповідь записують у «см»»; у `number` те саме, коли запис — та сама величина в іншій одиниці (`70 мм` при ключі 7 см, `2000 г` при 2 кг, `90 хв` при 1,5 год, `36 км/год` при 10 м/с; довжина, площа, об'єм з мл/л, маса, час з добою, гроші, швидкість — engine-unit-hint). Вердикт і тоді `bad`, а текст — «Перевір одиницю: переведи відповідь у «см».» (не «Одиницю можна й не писати»: без одиниці «70» знову неправильне; engine-unit-hint-p3) — не каже, що значення правильне: у задачі на переведення (`25 м = … см`), де дитина переписала дане умови `25 м`, він лише просить записати відповідь у потрібній одиниці. Інакше — звичайне «Зміни відповідь» (`9 мм` при ключі 7 см). Без `unit` запис з одиницею, як і раніше, неправильний.
- **Пояснення після «неправильно»** (`SLID_LEARN.badHint`): якщо спрацювала межа перевірки (кроки чи розмір, див. «Бюджет обчислень») — «Запис занадто складний для перевірки. Спрости його й спробуй ще раз.» (вердикт той самий, `bad`); чужа одиниця — див. вище; у `expression` знаменник-добуток без дужок (`k/6p`), якщо з дужками значення збігається з ключем, — «Знаменник-добуток візьми в дужки…»; `time` не у форматі години:хвилини — підказка формату; `quantity` без одиниць — «Допиши одиниці: м, см», в одиницях іншої величини — «Перевір одиницю», без останньої одиниці (`2 м 45`) — «Після кожного числа напиши одиницю», зі звичайним дробом (`2 9/20 м`) — «Звичайний дріб тут не розбирається…», час через двокрапку при `год`/`хв` (`3:20`) — «Тут час записують одиницями…»; `list` із самих чисел через кому з десятковою комою (`1,5, 2` — у полі `1.5, 2` стає саме так) — «Без «;» кома розділяє числа…». Усі тексти підказок для вправи віддає `SLID_LEARN.hintTexts(s)`.
- Відповідь має бути одним числом, однозначним за записом, або одним об’єктом зі списку `answerKind` нижче (пара координат, проміжок, вираз…). Дві різні величини («знайди НСД і НСК») — дві задачі.
- На кожен урок — 6–8 задач: приблизно 3 рівня 1, 2–3 рівня 2, 1–2 рівня 3.

Додаткові поля `answer`:
- `fractionOnly: true` — відповідь лише звичайним дробом; `reduced` і `mixed` зберігають попередні правила. Пробіли між розрядами (`19 735`) дозволено; десяткова кома/крапка — еквівалентні.
- `tol` — скінченна невід'ємна абсолютна похибка для числової відповіді (наприклад, `0.05` для округлення до десятих).
- `decimals: n` (ціле 0–6, лише `number`) — запис рівно з `n` знаками після коми (підказка під полем — своя: «Десятковий дріб — через кому, з одним знаком після коми: 3,5», приклад ніколи не ключ; `SLID_LEARN.numberHelp`): «округли до десятих» з ключем `"37,0"` і `decimals: 1` — `37` чи `37,00` дають `"form"` («Запиши відповідь десятковим дробом з одним знаком після коми»), `37,0` — `ok`. Ключ — **рядок** рівно з `n` знаками (`37.0` як число JS втрачає нуль — validatePool відхиляє). Сумісно з `tol`: `tol` перевіряє значення, `decimals` — запис (`3,14` при `"3,1"`, `tol: 0.05`, `decimals: 1` — `"form"`). Не поєднується з `fractionOnly`, `mixed`, `reduced`, `form`.
- `form: "improper"` (лише `number`) — відповідь неправильним дробом без цілої частини, протилежне до `mixed` (підказка під полем — «Неправильний дріб — через риску, без цілої частини: 7/3»): ключ `"7/3"`; `2 1/3` → `"form"` («Запиши відповідь неправильним дробом — без цілої частини»), `2,5` до `"5/2"` → `"form"` («звичайним дробом»), `14/6` — `ok` (нескоротність — окремо `reduced`). Ключ — неправильний дріб без цілої частини, без `mixed`.
- Однозначні записи, які `number` приймає без поля (рішення 2026-10-31, п. 5–6): префікс з однієї літери й «=» перед числом — `x = 5`, `b = 1`, `k=3`, `х = 3` (кирилицею); явний «+» перед числом — `+16`, `x = +16` = 16 (лише один «+» одразу перед цифрою: `+-16`, `+ 16`, `++16` — `bad`; від'ємний ключ «+» не задовольняє); періодичний десятковий дріб до раціонального ключа — `-0,(3)` = `-1/3`, `1,2(36)` = `68/55` (з `fractionOnly`/`reduced`/`mixed` — `"form"`: потрібен звичайний дріб). Те саме значення в `exactRoot`, якщо ключ раціональний, і в межах та елементах `intervalSet` (`[0,(3); 27]` = `[1/3; 27]`; у `list` і координатах — ні). Запис коренем, точне значення якого дорівнює ключу (`√576` при ключі 24, `2√144`, `∛27` при 3), — `"form"` «Обчисли корінь і запиши відповідь числом», ніколи `"ok"`; інше значення чи вираз без кореня (`20 + 4`) — `bad`. Відношення двох додатних чисел при ключі, записаному дробом (`1 : 4`, `2 : 8` при `"1/4"`; engine-answer-formats-ister п. 4), — `"form"` «Значення правильне, але це відношення. Відповідь тут — одне число…»; інший порядок (`4 : 1`), три члени, від'ємний ключ, ключ-ціле чи десятковий (`0.25`) — `bad`, як і раніше. У тесті рівня такий запис — `BAD`, як і раніше (чи зараховувати його там — питання людині).
- `scale: true` (лише `number`; engine-list-ordered п. 2, pg9m6 f08) — ключ — натуральне `n > 1` із масштабу `1 : n` («Запиши число n із масштабу 1 : n»): запис усього масштабу `1 : 10000`, `1:10 000`, `1 ∶ 10000` при ключі `10000` — `ok`, як і `10000`. Лише перший член рівно `1`: `2 : 20000`, `10000 : 1`, `1 : 1000`, `1 : 10000/1` — `bad`. Без `scale` запис `1 : n` при ключі-цілому — `bad`, як і раніше (там це може бути інше число). validatePool: `scale` — boolean лише для числової `answer` з натуральним ключем `> 1`. Під полем — кнопка «:» і підказка «Масштаб можна записати й повністю — через двокрапку (кнопка «:»)»: поле лишається `inputmode="decimal"`, а на цифровій клавіатурі телефона двокрапки немає (engine-list-p3 п. 4; `ratio` має «:» серед своїх кнопок).
- `signed: true` — показати кнопку «−» під полем числової відповіді, коли за класом її ще немає.
- Кнопки під полем числової відповіді (`SLID_LEARN.numberKeys`): «−» — з 6 класу, з `signed` або при від’ємному ключі; «/», «пробіл» і підказка про дроби й мішані числа — з 5 класу, при дробовому ключі або з `fractionOnly`/`mixed`/`reduced`. Клас — розділу вправи. У 4 класі для цілого ключа кнопок немає, для десяткового — лише підказка про кому. У класі, де знак або дроби вже вивчають, кнопки є в кожній вправі, тож вони не видають вигляд відповіді.
- `answerKind: "comparison"`: `answer` — `<`, `>` або `=`; дитина вводить знак.
- `answerKind: "list"`: `answer` — масив чисел або рядок чисел через `;`. Порядок довільний, повтори заборонено (з `multiset: true` у ключі — дозволено: порівнюються мультимножини, `2; 2; 3` = `3; 2; 2`, але ≠ `2; 3` і ≠ `2; 3; 3`; mer8g №655 — корені з кратністю); дроби й десяткові числа дозволено. `ordered: true` (engine-list-ordered) — порядок важливий: «Запиши ∠C і ∠D» з ключем `[41, 132]` приймає лише `41; 132`; переставлений запис `132; 41` — `bad` (значення на місцях неправильні) з підказкою «Перевір порядок: запиши величини в тій послідовності, у якій їх названо в умові.» (`badHint`; лише коли це ті самі значення в іншому порядку). Повтори з `ordered` дозволено (`50; 50`), `multiset` разом з ним — помилка validatePool; `±`/`∓` у ключі з `ordered` — теж помилка (розгорнуті елементи не мають заданого порядку; запиши їх окремо: `[-3, 3]`; engine-list-p3). Умова мусить назвати порядок (перелік величин). Запис з іншою кількістю елементів, ніж у ключі, — `bad` одразу, до розбору чисел (лінійно на довгих записах, engine-list-quadratic); елемент з понад чотирма `±` не розбирається (раніше мовчки випадав із переліку). У полі введення радимо `;`, щоб не плутати десяткову кому з роздільником. Префікс «x =» перед елементами (`x = 1; x = −2`, `x₁ = 1; x₂ = −2`, `x1 = 1, x2 = 3`, `x = 1`) знімається, лише якщо у формулах умови (`$…$` у `title`/`body`) рівно одна кандидатна змінна — мала латинська літера — і всі префікси запису — саме вона (кирилична `х` = `x`). Не кандидати: назва функції `f(x)`, `g(t)`; літера з індексом `a_n`, `log_a`; аргумент `\vec{…}`, `\overline{…}`, `\text{…}`; літера з числовим значенням в умові (`$a = 4,6$`); ліва частина `$y = (x + 5)^2 − 9$`, якщо `y` більше ніде не трапляється (нулі → лише `x`). Кілька кандидатів (`$3x^2 − bx + 12 = 0$`, система з `x` і `y`, `$y = kx + b$`, «ординати» при `$y = x^2$`, `$x + y = 2$`), чужа чи велика літера, різні літери (`x = 1; y = 2`), `BC = 3; 11`, умова без формул — `bad`, як і раніше. `x₁,₂ = ±3`, `x_{1,2} = (1 ± √5)/2`, `x1,2 = …` — один запис з `±`/`∓` на обидва корені за тим самим правилом літери; з будь-яким ключем `list` (до engine-answer-formats-ister — лише з `√`, `π` чи `±` у ключі); без `±` (`x₁,₂ = 3`) чи разом з іншими елементами — `bad`. Пробіли й перенос рядка одразу після «=» (`x₁,₂ =` ↵ `±3`) не заважають (engine-list-p3).
- `answerKind: "factors"`: `answer` — розклад на прості множники (`"2^3 · 3"`). Дозволено `*`, `·`, `×`, натуральні степені; складені множники не зараховуються.
- `answerKind: "divrem"` — ділення з остачею: `answer: [неповна частка, остача]` (два невід'ємні цілі). Дитина пише `3 ост. 2` (кнопка «ост.» на екрані), також приймаються `3 (ост. 2)`, `3 ост 2`, `3, ост. 2`, `3 остача 2`; якщо остача 0 — можна лише `5`. Правильна частка без остачі — підказка «Допиши остачу» і друга спроба. Остача, менша за дільник, — відповідальність автора. `unitForms` для divrem не можна (лише `unit`). Одна вправа «знайди частку й остачу» — це одна задача divrem, а не дві.
- `answerKind: "time"` — час доби, 24-годинний: ключ `"9:55"` (`Г:ХХ` або `ГГ:ХХ`, 0:00–23:59). Зараховуються `9:55`, `09:55`, `9.55` (у полі — `9,55`), `9 : 55`, `9 год 55 хв`, `9 год. 55 хв.`, `9 год` (= 9:00). Після `:`/`.` хвилини — рівно дві цифри: `9:5`, `955` → `bad` з підказкою формату («…хвилини — двома цифрами: 7:05»; приклад ніколи не ключ цієї вправи — `SLID_LEARN.timeExample`). Під полем — кнопка «:», цифрова клавіатура. Без `unit`/`unitForms`.
- `answerKind: "quantity"` — складена (іменована) величина: `answer` — невід'ємне число в **найменшій** з одиниць `units`; `units` — масив різних одиниць однієї величини з таблиці: довжина `мм см дм м км`, маса `г кг ц т`, час `с хв год доба`, гроші `коп грн`. Приклад: `answer: 245, units: ["м", "см"]`. Зараховується будь-який рівний запис з одиницями цієї величини: `2 м 45 см`, `245 см`, `2,45 м`, `2450 мм`, `2 м. 45 см.`, `2м45см`, розряди через пробіл `2 543 см` (групи рівно по 3 цифри; `25 43 см` — `bad`); кожна одиниця — не більше разу, між частинами — пробіл. Число без одиниць (`245`) → `bad`, «Допиши одиниці: м, см»; одиниці іншої величини (`2 кг 45 г`) → `bad`, «Перевір одиницю: тут відповідь записують у м, см». `form: "compound"` вимагає складеного запису в `units`: цілі частини від більшої одиниці до меншої, кожна менша за одну більшу одиницю (`2 м 45 см`; нульову частину можна писати чи ні) — `245 см`, `2,45 м`, `1 м 145 см`, `2450 мм` → `"form"` («Запиши його в м і см: спершу більші одиниці, потім менші, цілими числами»); ключ compound — ціле. Показ ключа й запис ключа для перевірки — складений (`SLID_LEARN.ansText` / `keyInput`: `2 м 45 см`). Кнопки поля — одиниці `units` від більшої; без `unit`/`unitForms`.
  `list` також приймає точні значення з `√`, `π` і `±`: `answer: "(-1 ± √5)/2"` — це два корені; дитина записує обидва через `;` у будь-якому порядку. Якщо в ключі `list`, `coordinates2/3` чи `intervalSet` немає `√`/`π`/`±`, кожен елемент має бути лише числом, як у чинному `list`: `32 - 24`, `3·3`, `2^1` не зараховуються. Запис `±3` / `∓3` (і `± 3`, `±1/2`, `±3; 0`) приймає будь-який `list` (engine-answer-formats-ister п. 1): ключ `[-3, 3]` чи `"-3; 3"` — те саме, що `"±3"`; у числовому ключі елемент з `±` — лише «±число» (`±3 + 0`, `±(3)`, `±±3` — `bad`), `+3` без `±` — `bad`, як і раніше; `±1,5` без `;` — це `±1` і `5` (підказка «відокремлюй знаком ;»). Кнопка `±` у полі — з 8 класу в кожному `list`, раніше — лише коли `±` чи корінь є в ключі.

**Символьні формати (пули 7–11 класів, матриця v2).** Назви `answerKind` збігаються з мітками стовпця «Формати» в docs/math-personalization-coverage.json. Учнівський запис розбирає власний аналізатор рушія (app/learn.js) у дерево; `eval` чи `Function` не викликаються, невідомий символ — «неправильно». Спільні правила запису: десяткова кома (крапка → кома), `−`/`-`, множення `·`/`*`/`×` або без знака (`3ab`, `2√3`, `2(x + 1)`, а також число одразу після дужок-множника: `(3x + 5)4x` = `(3x + 5)·4x`; після степеня, функції, кореня чи модуля — ні: `x²3`, `(x + 1)^2 3`, `sin(x)2`, `√(3)2`, `|x|2`, як і `x2`, — помилка запису; якщо `(x + 5)2` зі `^` замість числа правильне, дитина бачить «Степінь пиши через знак ^…»), ділення `/` або `:`, степінь `^` чи `²`/`³`, `√`/`sqrt`, `∛`, `∜`, `π`/`pi`, `|x|`, функції `sin cos tg ctg arcsin arccos arctg arcctg ln lg log_a`. Множники обчислюються зліва направо: `1/2x` = `x/2`, тож дріб зі змінною в знаменнику пишемо з дужками `1/(2x)`. `√` бере один множник: `√3x` = `√3 · x`, корінь з добутку — `√(3x)`. Аргумент функції без дужок тягнеться до наступного `+`/`−`/`/`, дужки чи функції: `sin 2x cos x` = `sin(2x) · cos x`, `sin x(1 + cos x)` = `sin x · (1 + cos x)`; аргумент-вираз пиши в дужках: `sin(x + 1)`. Літера `e` — звичайна змінна, не число Ейлера. Кирилична літера, що зовні збігається з латинською (`а е і к о р с у х`, `А В Е І К М Н О Р С Т Х`), читається як латинська: `5х + С` = `5x + C`, `у = 2х + 1`, `х = π/6 + 2πк, де к ∈ Z`; інші кириличні літери й слова (`ж`, «де C — стала») — помилка запису. Мішане число — лише окремим доданком: `x^3/3 + 3 1/3` = `x^3/3 + 10/3`, `(2 1/3)x`; у добутку, степені чи знаменнику (`2·1 1/3`, `x^2 1/3`, `3 1/3x`) — помилка запису, як і раніше. Кнопки під полем вставляють знак у місце курсора.

Підказка під полем називає ці записи в будь-якому полі з кнопкою «∛»/«∜», зокрема в `list`. Приклади в підказках під полем і в поясненнях не мають зараховуватися як відповідь вправи, біля якої їх показано: `tools/test-answer-ui.py` автоматично витягує приклади з усіх текстів вправи (`SLID_ANS_UI.field(s, клас).help` і `SLID_LEARN.hintTexts(s)`) і звіряє їх із ключем кожної answer-вправи змісту. Приклад для `time` і одиниці для `quantity` підбираються з самої вправи. `window.SLID_ANS_UI` — глибоко заморожена копія, лише для читання.
- `fig`/`img`/`cap` — та сама схема й правила ілюстрацій, що в уроці; зображення мають бути у credits.
- `srcPage` — додатний номер сторінки джерела; `adapted: true` позначає адаптовану вправу. Рядок «Джерело:» = назва джерела + посилання з `src` + «с. `srcPage`». Якщо посилання в `src` уже містить сторінку («mer5 с. 56, №1»), рушій `srcPage` не дописує (`SLID_LEARN.srcRef`), тож сторінка не подвоюється; нові вправи краще пишіть так: `src: "id №1"`, `srcPage: 56`.
- `unitForms: ["яблуко", "яблука", "яблук"]` — три форми одиниці для числової відповіді; біля поля форма оновлюється за введеним числом. `unit` лишається початковим підписом.

**Генератор `gen`** (engine-practice-pool) — обчислювальна вправа **рівня 1** з числовою відповіддю, числа якої беруться з діапазонів. Рушій і схема готові; у змісті генерованих вправ поки немає. Генератор не заміняє обов'язкових вправ з реальних джерел (задачі write-math-pool-*): він дає більше варіантів тієї самої дії за зразком вправи джерела.
```js
{ id: "g01", lesson: "g6m2l4", lvl: 1, sk: "ops", src: "mer6 №312", adapted: true, type: "answer",
  title: "Добуток {a} і {b}", body: "<p>Обчисли $ {a} · {b} $.</p>", steps: ["$ {a} · {b} = {a*b} $."],
  gen: { vars: { a: { min: 2, max: 9 }, b: { values: [11, 12, 13] } },   // ціла сітка min…max з кроком step (типово 1) або список values
         where: "a != b && mod(a*b, 3) == 0",                           // необов'язково: умова-вираз; набори, де вона хибна, відкидаються
         let: { s: "a + b" },                                           // необов'язково: похідні величини для where/answer/вставок
         answer: "a*b" } }                                              // вираз відповіді — ключ обчислює рушій
```
- Вирази — мова лабораторії (§8.1: `+ − * / ^`, `mod`, `round`, `abs`, порівняння, `&& ||`), без `eval`. Змінні — одна мала латинська літера (крім `e`, `x`). Інші імена у виразах і вставках — лише `let`, функції й сталі лабораторії (`pi`, `e`); невідоме ім'я — помилка.
- Вставки `{вираз}` у `title`, `body`, `hint`, `steps` — як шаблони лабораторії: `{a}` (до 2 знаків), `{a|3}` (3 знаки), `{a|s}` (доданок зі знаком), `{a|c}` (коефіцієнт — лише перед літерою чи дужкою: при 1 він порожній). Інші поля (`fbOk`, `fbBad`, `unit`…) не підставляються — вставка там помилка. Інші формати й TeX-групи у фігурних дужках (`\frac{…}`, `\text{…}`) у генерованій вправі не працюють — дроби пиши `$a/b$`.
- Кожна змінна має бути показана **в умові** окремою вставкою `{a}` (з форматом чи без) у `title` або `body` — не лише в `steps`/`hint` і не лише всередині виразу (`{a+b}`).
- Від'ємне значення вставки одразу після знака дії (`5 - {b}` при b = −3 → «5 − −3») — помилка: візьми вставку в дужки, пиши `{b|s}` або обмеж `where`.
- Поле `answer` не пишуть; `reduced`, `mixed`, `fractionOnly`, `decimals`, `form`, `answerKind` — не з генератором. `adapted: true` обов'язкове (числа відрізняються від джерела); `src` — вправа-зразок.
- Валідатор перелічує **всі** допустимі набори (2…5000) і для кожного перевіряє: відповідь — скінченне число з не більше ніж 6 знаками після коми (нескінченний дріб чи ділення на нуль — виключи в `where`), ключ сам проходить перевірку, кожна вставка обчислюється й показується без округлення. Екран (стиль, TeX) перевіряється на першому наборі (`genInstance(вправа, …, 0)`).
- Вибір набору детермінований: індекс = FNV-1a(`pool:id` + сесія) за модулем кількості наборів (`SLID_LEARN.genInstance`). Сесія — номер тренування `S.prN` (рушій збільшує його на старті), тож у межах сесії числа сталі, а в наступній — інші. Ключ прогресу `seen` і тема SRS — той самий `pool:id` для будь-якого набору: генерована вправа — одна задача пулу.

Перевірка: `node tools/validate.mjs --pool pg6m2`.

### Пули мовних предметів (українська мова; engine-pool-lang)

Файл `content/ukr/pool-g<клас>-<розділ>.js`, id пулу `p<розділ>` (`pu5s1`), id вправ — як у математиці (`a01`…). **id пулу й вправ — ключі прогресу, не перейменовувати.** Розділи «Пишемо самі…» (розвиток мовлення: u5s11, u6s14, u7s13, u8s14 і такі самі в 9–11 класах) — без пулу: письмо автоматично не перевірити (personalization-qa — помилка, make-tasks задач не створює); перевірювані уроки там (ділові папери: реквізити) — окремим рішенням пізніше.

```js
SLID.pool("ukr", {
  id: "pu5s3", section: "u5s3", status: "draft",
  meta: { author: "…", created: "2026-11-10", factcheck: "self", teacher: null },
  sources: [{ id: "z5", title: "Заболотний О. В. Українська мова. 5 клас. — Київ: Генеза, 2022", url: "https://…" }],

      hint: "Зміни слово так, щоб звук став під наголос.",
      steps: ["Ненаголошені [е], [и] перевіряємо наголосом.", "Село — се́ла, зима — зи́мній."] },
    { id: "a02", lesson: "u5s3l2", lvl: 2, sk: "oral", src: "z5 впр. 130", type: "stress", title: "Де наголос?",
      words: ["черг+овий", "кв+артал"], hint: "Згадай словник наголосів.", steps: ["Черго́вий, кварта́л — за орфоепічним словником."] }

```

- **Типи:** мовні вправи `gaps`, `pick`, `stress`, `word`, `split` (розмітка — §4.1, той самий `app/lang.js`), `sort` і `order` (поля — як в уроці, §4) — дитина пише чи позначає сама; `choice` / `multi` — лише поняттєві питання («чому так пишемо»), не замість правопису. Перелік `SLID_LEARN.POOL_TYPES` один для всіх предметів; правила `answer` / `choice` / `multi` не змінилися.
- **`steps` — пояснення**, 1–4 рядки: правило й розбір, чому саме так. Після відповіді дитина бачить його під заголовком «Пояснення» (у математиці — «Розв'язання»). `fbOk`, `fbText` не потрібні. `hint` — для рівнів 2–3 (без нього — попередження validate).
- **Перевірка й зарахування** — як в уроці: перша помилка — червоним лише хибне, підказка `hint`, друга спроба; друга помилка — правильна відповідь. **Часткового зарахування немає:** у SRS вправа «правильно», лише якщо все правильно з першої спроби (`gaps` з кількох пропусків — хоч один хибний = помилка теми).
- **Межі пулу:** `gaps` ≤ 6 пропусків (в уроці — 12), `stress` ≤ 6 слів, `pick` ≤ 40 слів-кнопок (як в уроці). Межі тесту рівня (§9: 3 / 3 / 20) у пулі **не** діють — тут є фідбек і друга спроба.
- **Заборонено** (помилка validatePool): поля числової відповіді — `unit`, `unitForms`, `answerKind`, `reduced`, `mixed`, `fractionOnly`, `decimals`, `form`, `tol`, `signed`, `units`, `gen`; `answer` — лише ключ слова в `word`; `hyp` / `poll` (тренування оцінює кожну вправу).
- `lvl` 1–3: 1 — одне правило, типовий випадок; 2 — кілька слів чи випадків, змішані з уже вивченим; 3 — виняток, пастка з уроку. На урок — 4–6 вправ (validate попереджає, якщо менше 4; personalization-qa `--strict` — менше 3 чи бракує рівня).
- `sk` — з `sk` екранів уроку (content/subjects/ukr.js); `src` + `sources` — реальні вправи підручника (номер, сторінка; `adapted: true`, якщо речення скорочено). Стиль і норма — як в уроках (милозвучність, заборонені фрази, D-041/D-042).
- Перевірка: `node tools/validate.mjs --pool pu5s3`, `node tools/personalization-qa.mjs --pool pu5s3` (матриці немає: ≥ 3 вправи й рівні 1–3 на кожен урок з оцінюваними екранами, `sk` — серед `sk` екранів уроку; прогалини — з `--strict`). Задачі на пули — `node tools/make-tasks.mjs --write-pool --subject ukr`.

## 11. Граф умінь (`SLID.graph`) — `content/<предмет>/graph.js`

Формальні залежності вмінь (дизайн: docs/design/skill-graph-math.md, ред. 4). **Змінює лише куратор**, як `plan.js` і `subjects/`; автори й верифікатори пропонують вузли й ребра рядком `IDEA GRAPH: …` в `memory/short/inbox.md`. Один файл на предмет; `tools/build.mjs` бере його в `index.html` і `sw.js` (офлайн) без змін збирача. Етап G1: рушій граф **не читає** — `SLID.graph` лише реєструє дані (`subject.graph`), їх перевіряють `tools/validate.mjs` і `tools/graph-report.mjs`. Етап G3: застосунок граф лише **читає** — пише вузли об'єкта в `item.u` події `answer` журналу (docs/EVIDENCE.md) за тим самим правилом прив'язки, що й інструменти (`SLID_LEARN.graphBind`, app/learn.js); `SLID_LEARN.nodeState` — похідний стан вузла, ніде не зберігається; для дитини нічого не змінюється. Стан учня (`S.skills`, `S.skw`, `S.mast`, `S.srs`, `S.errs`, `S.diag`, `S.seen`) не змінюється.

```js
SLID.graph("math", {
  v: "2026-11-15.1",                       // версія графа: дата + номер
  lines: {                                 // розмічені лінії: тут покриття V8 — дрейф (поза лініями — лише graph-report)
    frac: { lessons: ["g4m3l3", "m4a", "m1" /* … */], topics: ["dg4/parts", "dg6/frac" /* «тест/тема» */], st: "draft" }
  },
  nodes: [
    { id: "frac-mixed",                    // [a-z][a-z0-9-]*, унікальний, не збігається з жодною sk; ніколи не перейменовується
      sk: "frac",                          // батьківська навичка з content/subjects/<предмет>.js — рівно одна
      name: "Перетворювати неправильний дріб на мішане число й навпаки",   // одне речення мовою вчителя
      teach: ["m5"],                       // уроки, де вміння пояснюють: id або { l: "m3", by: "u" } (додатковий вузол пари)
      pre: [{ u: "div-rem", w: 2, why: "m5 #4, #5: ділення з остачею (pre: m4a)" }],   // w: 2 «без цього не вийде», 1 «допомагає»
      part: [], same: [],                  // { u, why }: part — названий крок алгоритму; same — той самий прийом на іншому матеріалі
      st: "draft" },                       // draft → verified → approved (approved — лише людина); зміна ребер чи teach повертає в draft
    { id: "div-table", sk: "num", name: "Ділити в межах таблиці множення", base: true, g: 3, st: "draft" },   // опора без уроку (baseline-теми)
    { id: "old-id", sk: "frac", name: "…", teach: ["m1"], gone: "frac-read", st: "draft" }                    // застарілий: перенаправлення
  ]
});
```

**Поле `u` у змісті** (необов'язкове; ставить автор у своєму файлі): рядок або масив з 1–2 різних id вузлів на **оцінюваному** екрані уроку, вправі пулу, темі тесту або завданні тесту. Без `u` об'єкт отримує вміння за правилом (§2.4 дизайну):
1. є `u` — беремо його (на `gone`-вузол — через перенаправлення);
2. інакше — **типовий вузол пари** (урок, `sk`): вузол з тією самою `sk`, у якого урок стоїть у `teach` без `by` (у парі він щонайбільше один);
3. вузол `{ l, by: "u" }` отримує лише об'єкти з явним `u` — його ставлять на ті екрани й вправи, що перевіряють друге вміння уроку;
4. boss-урок — типові вузли уроків свого розділу; кілька кандидатів — «неоднозначно» (лише звіт, якщо boss-урок не доданий у `lines`);
5. завдання тесту: `u` завдання → `u` теми → типові вузли з `sk` завдання уроку `lesson` завдання (якщо задано — §9), інакше уроків `topic.lessons`; вузли теми — об'єднання вузлів її завдань (або `u` теми). Baseline-тема — `u` на `base`-вузол;
6. екран, що повторює вміння **іншого** уроку (той, що має `pre`), — `u` на вузол того уроку: обов'язок автора;
7. немає ні `u`, ні типового вузла — об'єкт лише в `sk`, як раніше (у лінії дозволено для пар з < 3 об'єктами).

**Перехідний стан після `gone` з іншою `sk`.** Якщо куратор замінив вузол новим з іншою `sk` (старий — `gone`), `u` автора на старий вузол через перенаправлення тимчасово веде до вузла з чужою `sk` (V10б попереджає, V5 не спрацьовує — перевіряється `sk` самого `gone`-вузла). Такий об'єкт **не враховується** в стані вузла (G3 `nodeState`, `preWeak`), доки автор не оновить `u`.

`u` не впливає на перевірку відповіді й на прогрес: для `diff-answers --content-old` це не зміна суті завдання (`rev` не потрібен).

**Перевірки** (таблиця §3 дизайну; повідомлення починаються з «граф V…»):
- **помилка `validate`** (той, хто спричинив, виправляє у своєму файлі): V1а — формат графа й вузлів (`id`, `sk`, `name`, `st`, `teach`, `by` лише `"u"`, `base` + `g`, `w` ∈ {1, 2}, непорожній `why` у кожного ребра, `lines`); V2 — `u` (формат, наявний вузол, лише на оцінюваному екрані), ребра й `gone` на наявні вузли, без петель і дублікатів; V3 — цикли в `pre ∪ part`, `same` між з'єднаними шляхом; V5 — `sk` об'єкта з `u` = `sk` вузла (для теми — серед `sk` її завдань; baseline-тема — лише `base`); V6а — два типові вузли в парі; V7а — вузол без `teach` і не `base`; V10а — ланцюжки `gone`, ребро на `gone`-вузол;
- **дрейф** — попередження `validate` з текстом «потрібна правка graph.js — допиши в inbox для куратора», автора й CI не блокує: V1б — `teach`/`lines` на неіснуючий урок чи тему; V4 — передумова пізніша за урок (порядок: клас, `weeks[0]` розділу, індекс уроку в розділі; однаковий `weeks[0]` різних розділів — нічия, дозволено); V6б — урок `teach` без екрана з `sk` вузла; V7б — вузол без прив'язаних об'єктів, `by: "u"` без явного `u` у своєму уроці; V8 (лише в `lines`) — урок лінії поза `teach`, завдання теми лінії без вузла, пара без вузла з ≥ 3 об'єктами, неоднозначний boss-урок, явно доданий у лінію;
- **попередження V10б** — `u` на `gone`-вузол: «онови u: старий → новий».

`validate --section <id>` (`--diag`, `--pool`) показує знахідки графа лише для уроків цього розділу (цього тесту, пулу); повний прогін і CI — усі.

**Звіт:** `node tools/graph-report.mjs [--subject math]` → `reports/graph-<предмет>.md` (у .gitignore; номери екранів і завдань — від 1, як у validate): цифри графа, V8 поза лініями, V9 (старі `pre`, `requires`, `forEvidence`, `prerequisites` матриці проти шляхів графа; ребра графа без старого джерела), типовий вузол розщеплених пар, пари без вузла, нічиї V4, неоднозначні boss-об'єкти. `--since <коміт>` — змінені вузли й додані/змінені об'єкти розщеплених пар та їхніх тем (за хешем вмісту: вставка екрана не робить змінними наступні). `--strict` — rc 1 на помилці чи дрейфі (усі лінії й увесь граф — прохід куратора); `--line <id> --strict` — лише лінія (прийняття лінії, G2/G5). `--uses <вузол>` — де стоїть явний `u` на вузол (зміна `sk` вузла — лише новим вузлом з `gone` на старому або одним пакетом із задачами авторам).
