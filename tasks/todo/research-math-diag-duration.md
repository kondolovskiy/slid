# Підготувати й провести пробне проходження діагностик учнями

## Мета й межі

10–15 хв — початкова гіпотеза, не встановлений результат. Автоматичний плейтест вводить готові відповіді й перевіряє механіку. Ця задача перевіряє реальне читання та розв’язання учнями; вона не блокує написання, незалежну перевірку змісту чи технічне класове приймання.

Кожен клас можна залучати після qa-math-personalization-gN для нього; підготовка протоколу починається відразу. Це умова проведення, не глобальна залежність від усіх класів.

## Що зробити

1. Підготувати docs/testing/math-diag-duration.md: сценарій добровільного пробного проходження, критерії добору учнів відповідного класу з різною підготовкою, порядок фіксації результатів без імен та зайвих особистих даних. Не контактувати з учнями чи іншими людьми самостійно; організацію й доступ забезпечує Віктор/учитель.
2. Фіксувати клас і версію тесту, кількість показаних завдань, активний час читання/розв’язання, перерви окремо, самостійне чи допоміжне проходження, завершення/відмову й місця труднощів. Враховувати адаптивне скорочення: не змішувати результати різної довжини в одну непояснену оцінку.
3. Для кожного класу описати фактичну кількість учасників, медіану й діапазон часу, типові труднощі та обмеження малої вибірки. За нестачі учнів прямо лишити клас без перевіреної оцінки; не замінювати учнів дорослим або ботом.
4. За результатами запропонувати скорочення/переформулювання збереженням потрібних умінь. Зміни контенту — окремими задачами з повторною незалежною перевіркою; id і збережені результати не змінювати без плану міграції.
