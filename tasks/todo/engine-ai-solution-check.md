# ШІ-перевірка ходу розв'язання в тренуванні

## Навіщо
Запит Віктора (2026-10-13): зараз у тренуванні (пул задач, docs/PERSONALIZATION.md §3) перевіряється лише записана відповідь. Далі ШІ має перевіряти й **послідовність виконання**: де саме в розв'язанні помилка, а не лише «відповідь не та».

## Що вже готово під це
- Кожна задача пулу має `steps` — еталонне розв'язання кроками, і `src`, `sk`, `lesson`, `lvl` (CONTENT_SCHEMA §10).
- Помилки вже пишуться в журнал (`LEARN.record`) і ведуть до порад «Варто повторити».

## Що зробити
1. **Введення ходу розв'язання.** Варіанти: (а) поле «чернетка» — кілька рядків тексту/формул під задачею; (б) фото зошита; (в) покрокове введення (рядок за рядком). Почати з (а) для задач рівня 2–3; для рівня 1 лишити лише відповідь.
2. **Перевірка.** Запит до моделі Claude: умова, еталонні `steps`, відповідь, хід розв'язання дитини → структурована відповідь `{ verdict: ok | slip | method, step: n, note: "…" }` (обчислювальна помилка чи неправильний метод, на якому кроці, коротке пояснення для дитини без готової відповіді).
3. **Офлайн.** Застосунок працює без мережі (D-002): перевірка ШІ — лише коли є інтернет; без нього — нинішня перевірка відповіді, а чернетка зберігається й перевіряється пізніше. Ключ API не може лежати в клієнті — потрібен проксі (разом із синхронізацією, ROADMAP).
4. **Зв'язок із персоналізацією.** `verdict: method` → запис у `LEARN.record` з міткою типової помилки (нове поле `err`), щоб `detect` бачив «ту саму помилку» точніше, ніж за темою.
5. **Безпека й вік.** Дані дитини: що надсилається, згода батьків; фільтр відповіді моделі (тон, без оцінок особи); ліміти запитів.

## Відкриті питання до Віктора
- Чернетка текстом чи фото зошита? (фото природніше для 6 класу, але дорожче й складніше)
- Який бекенд для проксі й хто платить за запити?
- Чи показувати дитині вердикт ШІ одразу, чи спершу вчителю/батькам?
