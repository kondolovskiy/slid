# Повторний тест рівня з добором завдань із пулу

Перенесено з engine-practice-pool (пункт 5 «Діагностика з пулу»): там його не реалізовано, бо він потребує рішень людини й окремої перевірки сумісності зі збереженими тестами. Відповідальна — ця задача.

## Що є зараз
- Повторний тест — той самий `SLID.diag` (ті самі `items`, ті самі індекси). Відповіді зберігаються вердиктами за індексом (`S.diagRun[id][i]`, `S.diag[id].res[i]`), редакції — `rev` (CONTENT_SCHEMA §9, `resumeDiag`).
- Початкові коробки SRS з нового результату тесту (ok → box 2, shaky → box 0) уже є: `SLID_LEARN.srsFromDiag` (engine-practice-pool).

## Пропозиція (потребує рішення)
1. Повторний тест бере для теми не ту саму пробу, а вправу з пулу уроку `topic.lessons` (рівень 1 — базова, рівень 2 — складніша), щоб дитина не відповідала вдруге на те саме завдання.
2. Добір фіксується в момент старту повторного запуску: `S.diagRunPick[id] = [{ i, key: "pool:id" }]` + `rev` тесту; **порядок і склад items розпочатого тесту не змінюються** при продовженні, зміні змісту чи пулу (за відсутності вправи — запасна проба з тесту з тим самим індексом).
3. Вердикти й надалі за індексом завдання; `buildPlan`/`topicStatus` — без змін; для known (тема cur) — лише проба з тесту (одна вправа пулу не покриває ядра уроку, CONTENT_SCHEMA §9 «Тема cur і known»).
4. Формати: лише `DIAG_ANSWER_KINDS` (number, time, quantity) і без `form` у ключі, бо в тесті `form` = неправильно без пояснення; вправи з `gen` — з тим самим детермінованим seed.

## Відкриті питання до Віктора
- Чи брати вправи пулу (вони з підручника, інші за складністю, ніж проби тесту) для оцінки ok/shaky/gap? Чи це лише для тем pre, а cur — завжди проби тесту?
- Що робити, якщо дитина вже бачила вправу пулу в тренуванні (seen) — брати її чи ні?
- Чи зараховувати повторний тест з пулу в `S.diag` так само, як основний (перераховує план і коробки SRS)?
