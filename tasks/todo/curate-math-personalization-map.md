# Узгодити покриття діагностик і пулів математики 4–11 класів

## Передумова спільних навичок

curate-math-diag-g6-links має бути done після власної незалежної перевірки. Використати зафіксовані нею sk й терміни як базову лінію; не створювати дубльованих ключів пропорцій/подільності й не перейменовувати старих. Обидві кураторські задачі належать math-curation й не редагуються паралельно. Перевірка curate-math-diag-g6-links не залежить від цієї матриці чи пакетного verify-g6.

## Результат

`docs/math-personalization-coverage.md`: матриця «клас → розділ → тематичний урок → передумови → діагностична тема/завдання → пул → формат відповіді». Зберегти сталі id чинних уроків, dg6 та pg6m1…pg6m5.

## Що зробити

1. Взяти всі 50 розділів із реєстру: 6/6/5/8/6/7/6/6 для класів 4–11. Врахувати m4s1 поза plan.js. Відокремити boss від тематичних уроків.
2. Для діагностики вибрати ключові опори попередніх класів, а не скласти річну контрольну: типово 8–12 тем pre по 2 завдання + по одній репрезентативній cur на кожен розділ (споріднені короткі розділи можна об’єднати з поясненням). Орієнтир 20–32 завдання; час 10–15 хв — гіпотеза для окремого учнівського пілоту research-math-diag-duration, а не результат автоматичного плейтесту.
3. Для кожної pre обґрунтувати lessons (1–2 реальні уроки; виняток для 4-го — контракт baseline без вигаданих lessons), for (конкретні розділи поточного класу), item.lesson для точного повторення. Для cur не приписувати володіння всім розділом за одним завданням: lessons лише на перевірене вміння.
4. Звірити базову лінію з Мерзляком (D-024), для 4-го — спільне чинних підручників і D-025. Відкрити джерела; занотувати видання, URL, сторінки. Для кожного уроку ввести curricularScope: required | optional | pending, із джерелом і поясненням. required — підтверджений матеріал базового курсу відповідного класу; optional — підтверджений профільний/додатковий матеріал; pending — невирішена розбіжність, яку передати Віктору за правилами пам’яті. Не вигадувати рішення про перенесення уроку між класами.
4а. Окремо розібрати g11m2l3 (рівняння площини), розташування координат/векторів у 10–11 класах та інші відкриті питання handoff. Невирішене не включати у обов’язкову діагностику й не використовувати для висновку про прогалини учня базового курсу. optional не відкривати автоматично як обов’язкову наступну тему; якщо чинний UI цього не відрізняє, інтеграцію такого матеріалу відкласти з явною причиною.
4б. Куратор у межах цієї задачі оновлює переліки й критерії залежних авторських та перевірочних задач: указує required/optional/pending біля конкретних уроків, перераховує обов’язкову кількість вправ і покриття. Не змінювати сталі id й не видаляти задачі мовчки. Для розділу без required-уроків позначити задачу відкладеною в нотатках; done не ставити без результату. Одночасно вилучити її id з обов’язкових depends_on задач перевірки/приймання та записати окремим необов’язковим посиланням у їхніх нотатках і матриці. Переліки очікуваних файлів/пулів і команди перевірки також перерахувати; відсутність відкладеного пулу не є помилкою required-покриття. Якщо required-теми повернулися до матриці — відновити залежність і повторити відповідне приймання. Зафіксувати версію матриці, на яку спираються виконавці.
5. Для 4-го скласти список умінь 1–3 класів без вигаданих id уроків. Передати в engine-math-diag-g4-baseline вимоги до представлення прогалин і доступної допомоги; не створювати окремі предмети чи повний курс 1–3 класів.
6. Для кожного тематичного уроку запланувати 6–8 реальних вправ трьох рівнів; поняттєвий урок — мінімум 5 з обґрунтуванням. Указати де потрібні відношення, координати, точні корені, множини розв’язків або символічний вираз: це вхід для engine-math-pool-answer-formats.
7. Зіставити sk з предметним словником і вже завершеним результатом curate-math-diag-g6-links; не делегувати нові зміни закритій задачі й не змінювати її прийнятий результат заднім числом. Нові загальні навички додає куратор цієї матриці, не автори файлів. Якщо матриця виявила нову потрібну правку dg6/pg6, створити окрему наступну задачу з незалежною перевіркою; внести її до залежностей verify/qa 6-го класу, якщо вона потрібна для його обов’язкового покриття. Матриця фіксує висновок і не залежить від цієї наступної задачі; нова задача може залежати від матриці, але не навпаки. Так зберігається порядок без прихованого циклу або повторного виконання вже закритої роботи.

## Готово, коли

- [ ] Матриця інвентаризує всі 8 класів, 50 розділів і 182 тематичні уроки; для кожного задано curricularScope. Обов’язкове покриття рахується лише за required; optional/pending видимі окремо й не зараховані як виконане.
- [ ] Кожне посилання на урок/розділ перевірено по реєстру; межі діагностики й пулу різні та явно описані.
- [ ] Прогалини форматів і випадок 4-го класу передано відповідним задачам; чинний контент не переписано без потреби.
- [ ] Залежні задачі узгоджено з матрицею; невирішені питання мають джерела й адресата. Наявність pending в одному класі не блокує авторство й перевірку required-тем інших класів. Матриця передана в review; зміни контенту пройшли validate і потрібний build.
