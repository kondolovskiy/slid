## Вимоги

- Для кожної pre рівно два завдання: базове, потім складніше; кожна cur має одне завдання. Орієнтир 8–12 pre та репрезентативні cur по required-темах розділів, 20–32 завдання; відхилення обґрунтувати. Для 4-го застосувати контракт baseline, не вигадувати уроки 1–3 класів.
- Почати з легкого, чергувати теми, cur — у другій половині. Перевіряти навчальну мету, не швидкість довгих обчислень; 10–15 хв — лише попередня оцінка часу читання й розв’язання. Автоматичний плейтест перевіряє механіку та не підтверджує тривалості для учня. Фактичний час перевіряє окрема задача research-math-diag-duration на пробному проходженні учнями.
- Різні придатні типи з DIAG_TYPES; числова відповідь лише коли приймається поточним парсером. Не переносити в діагностику тип answer з пулів без підтримки схеми. Для геометрії й графіків дати достатній рисунок/дані, доступний опис.
- Жодних fbOk/fbBad/fbText, hint, poll/hyp, XP або вбудованого варіанта «не знаю»: це робить режим тесту. Приховати дані елементів керування, що підказують відповідь; перевірити hideDen, signed та lab.out.
- Кожна тема pre веде до точних уроків повторення і релевантних for; item.lesson звужує крок shaky. cur.lessons не позначає відомими неперевірені вміння.
- Розв’язати всі завдання двічі; перевірити ключі, еквівалентні записи, типові помилки дистракторів та їхні позиції. Нотація за D-024/D-025.
