# Фронтенд: вхід, код привʼязки й синхронізація прогресу

Сервер готовий: docs/BACKEND.md (API v1). Без цього клієнта бекенд нікому не потрібен.

## Що зробити
- **Злиття стану** — чиста функція в `app/` (як learn.js) з тестами в `tools/`: бали за день сумуються з двох пристроїв, зірки/best — максимум, done — або, errs/mast/skw — обʼєднання за часом, planByGrade, srs… Пройти всі поля ARCHITECTURE.md «Стан користувача»; жодне не губиться.
- **Синхронізація**: `GET/PUT /v1/progress`, при 409 — злити й повторити; офлайн — черга, відправка при появі мережі. Застосунок працює без сервера як зараз. `name` не відправляти.
- **Профіль**: «Увійти шкільним акаунтом» (Google Identity Services, `id_token` → `POST /v1/auth/google`). Якщо на пристрої є анонімний прогрес — **спершу спитати** «Це твій прогрес на цьому пристрої?»; лише на «так» — `link: true` (рев’ю server-auth Б-1: спільні шкільні ПК). На «ні» — вхід без привʼязки, локальний чужий прогрес не зливати.
- «Код для іншого пристрою» (`POST /v1/pairing`, показ коду й таймера 10 хв) і «Ввести код» (`/v1/pairing/claim`).
- Помилки: 401 — «акаунт не шкільний / код невірний або прострочений», 429 — «зачекай хвилину», 503 — «спробуй пізніше».
- Адреса API — конфіг збірки; CSP/SW: не кешувати відповіді API.

## Нотатки з паралельної сесії (персоналізація / Evidence V2), 2026-11-01
Щоб не було конфліктів, врахуй, що вже є в основі:
- **Ключі localStorage:** синхронізувати лише `slid.v1`. Не відправляти й не зливати `slid.evidence.pending` (черга журналу подій, docs/EVIDENCE.md) і майбутній `slid.hyp` (гіпотези, docs/design/diag-hypothesis-math.md §2.5) — це локальні дані пристрою.
- **`save()` в app/app.js** уже змінено (engine-evidence-p3): при невдачі запису `slid.v1` видаляє `slid.evidence.pending` і повторює. Синхронізацію чіпляй поруч, не переписуючи цей резерв.
- **Журнал подій** (`app/evidence.js`, IndexedDB `slid-evidence`) — окремий від стану; має `did` (анонімний id пристрою) і `pid` (профіль, новий після «Скинути прогрес»). Дані пілоту (рішення людини) підуть через бекенд — потрібен окремий ендпоінт подій (напр. `POST /v1/events`, пакети з `eid` для ідемпотентності); це окрема задача, не в цій.
- **Нові поля стану** з цієї сесії: `S.diag[id].res[i]` може бути 0.5 (півбала, engine-diag-half-credit); SRS-записи з `src: "diag"` (D-032); `S.diagRun`, `S.diagRunRev`. Функція злиття має їх знати.
- Паралельно в app.js іде робота engine-hyp-e2-shadow (виклики трекера гіпотез після `setDock` у `check()`); тримай зміни в app.js локальними.
