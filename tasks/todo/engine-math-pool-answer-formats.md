# Закрити формати відповідей, потрібні пулам 7–11 класів

## Межі

Це єдиний виконавець форматів із початкового пункту 3 engine-practice-pool; у залишковій задачі лишено лише вибір одиниці. Не реалізовувати генератори чи автоматизацію створення задач. comparison/list/factors, fractionOnly, tol, srcPage/adapted/unitForms уже реалізовані в engine-diag-pool-answers. Не реалізовувати їх повторно. Звичайний list не означає впорядковану пару координат.

## Що зробити

1. За матрицею зафіксувати конкретні вправи, які не виражаються чинним answer: відношення, впорядкована пара/трійка координат, точна відповідь із коренем/π, проміжок або множина розв’язків, еквівалентний вираз. Визначити мінімальну потрібну підтримку, не загальну систему комп’ютерної алгебри.
2. Для кожного потрібного формату описати контракт, припустимі еквіваленти, порядок, роздільники, область визначення, округлення й приклади правильних/неправильних записів. Підтримати в checkAns, validatePool та UI answer разом; без eval учнівського вводу.
3. Два корені без порядку можна подати чинним list; для впорядкованих координат потрібна окрема семантика. Якщо потрібного формату немає, не підміняти перевірюване вміння запитанням про кількість відповідей чи десятковим наближенням без дозволу умови.
4. Поняттєві питання choice/multi допустимі за схемою, але ними не замінювати всі вправи зі самостійним записом відповіді. Доведення не оголошувати автоматично перевіреним за одним числом.
5. Документувати §10; узгодити з engine-practice-pool виконаний підскоуп. Генератори, випадковий добір діагностики з пулу та AI-перевірка ходу не входять у цю задачу.

2026-10-30, редактор personalization-shared (worktree-агент оркестратора). Основа — b8a3552 (після baseline 4 кл.). Звіт: reports/qa/engine-math-pool-answer-formats.md.

**Рішення.** Назви `answerKind` = мітки матриці v2: `ratio`, `coordinates2`, `coordinates3`, `exactRoot`, `intervalSet`, `expression`, `periodicSet` (+ чинні number/comparison/list/factors). Так аудит personalization-qa рахує формат без таблиці перекладу. Один власний аналізатор (лексер → дерево, без eval/Function), два обчислювачі: точний (сума q·ⁿ√r·π^k на BigInt) для exactRoot/координат/списку/меж проміжків і числовий (48 детермінованих точок) для expression/periodicSet.

**Потреби матриці → формат:**
- відношення g6m3l1–l2 → `ratio` (порядок, рівні відношення; `reduced` — натуральні без спільного дільника);
- пари координат g6m4l5, g7m7 (розв’язок системи), g9m2, g9m6 → `coordinates2` (порядок і знак, компоненти можуть мати √); `coordinates3` для відкладеного g11m2 — той самий код;
- точні корені/π g8m3, g8m5, g9m2, g9m4, g9m6, g10m3–g10m5, g11m4 → `exactRoot`; два корені рівняння — `list` з √ і ± (обидві гілки, без порядку);
- проміжки g9m1, g9m3, g10m1, g10m6, g11m1 → `intervalSet` (межі, об’єднання, ізольовані точки, ∅, R);
- вирази g6m5, g7m3, g8m1, g9m2, g9m3, g10m3, g10m5, g10m6, g11m1, g11m3, g11m4 → `expression`; щоб «розкрий/розклади/скороти/спрости» не зараховувало переписану умову — `form`: expanded / factored / reduced / simplified; рівняння прямої/кола — `expression` з `=` (рівносильні, якщо L − R пропорційні);
- тригонометричні рівняння g10m5l4 → `periodicSet` (±, (−1)^k, кілька серій; k/n/m; «k ∈ ℤ» біля поля).
Жодну потребу не підмінено кількістю розв’язків чи наближенням; тому окремо погоджувати choice/multi замість формату не довелося.

## Обсяг за матрицею 2026-10-16.v2

Вхід: docs/math-personalization-coverage.json **2026-10-16.v2**, поле formats кожного уроку. Number/list/comparison/factors — чинні можливості; ratio, coordinates2, exactRoot, intervalSet, expression, periodicSet — потрібні розширення required.
