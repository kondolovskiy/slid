# Формат відповіді «частка + остача» для пулів (answerKind: divrem)

## Проблема

Ділення з остачею дає дві величини. Правило §10 «одна відповідь — одне число» змусило pm4s1 питати окремо частку або остачу, тож вправи «знайди неповну частку й остачу» (Логачевська 4 ч.1 №3, №11) не беруться (reports/verify/write-math-pool-m4s1.md, прогалина 1). Рішення людини 2026-10-22: зробити формат divrem.

## Що зробити

- `answerKind: "divrem"` для `type: "answer"`: `answer: [частка, остача]` — два невід'ємні цілі. Дитина пише `3 ост. 2`, `3 (ост. 2)` або `3 ост 2`; при остачі 0 — також просто `3`. Кнопка «ост.» на екранній клавіатурі.
- checkAns: ok лише при збігу обох; правильна частка без остачі — підказка дописати остачу; без eval.
- validatePool, показ правильної відповіді, CONTENT_SCHEMA §10, тести (test-learn, test-answer-ui fixture), старі формати без змін.

## Нотатки виконавця

**Контракт.** `answerKind: "divrem"` лише для `type: "answer"`; `answer: [q, r]` — масив двох невід'ємних safe-цілих (рядок-ключ — помилка валідатора). Учень: `3 ост. 2`, `3 (ост. 2)`, `3 ост 2`, `3ост2`, регістр і зайві пробіли неважливі, кома після «ост» допустима, розряди через пробіл (`1 234 ост. 5`). Лише частка: при r = 0 — ok, при правильній q і r ≠ 0 — "form" («Неповну частку знайдено. Допиши остачу…», друга спроба), інакше bad. Без eval, лише регулярні вирази. Остача < дільника — відповідальність автора (дільник рушію невідомий).

**UI (app/app.js).** Поле inputmode numeric, кнопка «ост.» вставляє « ост. »; підказка під полем; для divrem поле не замінює крапки на коми; показ правильної відповіді «7 (ост. 1)» + unit. Інші формати не змінено.
