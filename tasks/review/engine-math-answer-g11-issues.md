### Що зроблено (app/learn.js, app/math.js)
1. **Кирилиця в символьних записах** — `norm()` (усі символьні формати: expression, coordinates-вирази й числові координати, exactRoot, intervalSet, periodicSet, list у точному режимі) читає кириличні двійники латинських літер (`а е і к о р с у х`, `А В Е І К М Н О Р С Т Х`) як латинські. Прийнято (`ok`), не підказка: гліфи візуально тотожні, кнопок літер немає, `number` уже приймає `х = 3`. Безпечність: раніше будь-яка кирилиця робила запис нерозбірним, тож нове `ok` можливе лише там, де запис після заміни тотожний ключу; не-двійники (`ж`), слова («де C — стала», «або») лишаються `bad`. Суфікс periodicSet «де k ∈ Z» з кириличними «де», «к» — враховано. number/list-префікс, divrem («ост.»), time, quantity, одиниці (`stripUnit` до norm) — без змін.
2. **Стала первісної `c`** — консервативно `"form"` (не `ok`) з підказкою «Вираз правильний. Сталу запиши великою латинською літерою C.». Умови: ключ має доданок `+ C` (велика латинська C, малої c немає), запис має малу c і жодної C, у тексті умови (title, body, q, text, hint: формули й текст поза тегами, без TeX-команд і латинських слів) окремої латинської `c` немає; тоді запис з C замість c порівнюється з ключем. Чому form, а не ok: усі 3 реальні вправи (pg11m3 a01–a03) прямо просять «Сталу запиши великою літерою $C$»; form не зараховує, але й не каже «неправильно» правильній відповіді. Кирилична велика `С` — двійник, тобто `ok` (п. 1). `K`, `5x + c + C`, `6x + c`, `5x + C + c − C`, c з умови — `bad`.
3. **Мішане число у виразі** — `parseTree.mixedNum`: «ціле пробіл ціле/ціле» (правильний дріб, без коми) лише як окремий доданок на початку доданка; після нього — лише `+ − ) = |` чи кінець (інакше зайві лексеми → запис не розбирається). `x^3/3 + 3 1/3`, `-2 1/3 + x`, `(2 1/3)x`, `|x| + 2 1/3` → ok; `31/3`, `3 1/3x`, `3 1/3·x`, `2·1 1/3`, `x^2 1/3`, `1/2 1/3`, `3 4/3`, `3 0/3`, `3,5 1/2`, `3 1/3^2` → bad, як і раніше. Побічно: exactRoot `2 1/3 + √2` до `7/3 + √2` тепер ok (той самий канонічний доданок, що `7/3`).
4. **`√576` при ключі 24 (number)** — `"form"` «Значення правильне. Обчисли корінь і запиши відповідь числом.», лише коли запис — стала з коренем і його точне значення раціональне й дорівнює ключу; ніколи `ok`. `-√576` до 24, `√577`, `√576 + 1`, `20 + 4` (без кореня) → bad. Невдала спроба точної арифметики не змінює підказку `bad` (LIMIT відновлюється — як було).
5. **Періодичний дріб у межах intervalSet** — `[0,(3); 27]` = `[1/3; 27]`, також `{0,(3); 2}`, межі з коренем у ключі. `list` і координати — без змін (поза задачею; див. відкриті питання).
6. **`\lg`** — у COMMANDS/FN `app/math.js` (прямим шрифтом, як `\log`). Уніфікація з уроками (HTML «lg $b$»): назва функції перед аргументом без дужок дістає тонкий пробіл (`\lg 100` → «lg 100», `\ln x`, `\sin φ`, `\sin 60°`); після `_`, `^`, `(`, `{`, `\,`, `\left`, операторів — без пробілу. Зміст пулів (`\text{lg}\,`) не змінював — пропозиція куратору нижче.
7. **Показник кореня** — `<sup class="root-index" style="order:-1">` усередині `.sqrt`: показник стоїть перед знаком √ (знак малює `.sqrt::before` у flex-рядку). Розмітку не змінено (показник лишився всередині `.sqrt`), тож `plainNode` в app.js дає той самий текст для атрибутів; CSS у index.html не чіпав. Перевірено знімком (Chromium): «³√x²», «⁶√x».
8. **Відкриті питання g10:**
   - `number` приймає будь-яку літеру (`y = 5`): **лишено як є**. Це записане рішення 2026-10-31 п. 5 (CONTENT_SCHEMA §10: `b = 1`, `k=3`), змінювати його — рішення людини. Відмінність від list: у number ключ — одне значення, і правильне число з чужою міткою не стає хибним значенням іншого кореня; у list помилкова літера приписувала кілька значень чужій величині (P1-1). Пропозиція в inbox.
   - `x₁,₂ = …` у list: `LIST_PM` — один запис з `±`/`∓` (`x₁,₂ = ±3`, `x_{1,2} = …`, `x1,2 = …`), та сама вимога «єдина кандидатна змінна умови» (`taskVar`), лише коли `±` дозволено ключем (точний режим). Без `±` (`x₁,₂ = 3`), разом з іншими елементами, чужа літера — bad. Реальні вправи (pg8m5 a04, a05, b05; pg10m3 a07): префікс знімається лише з `x`.
   - Мутація `!(xr === null && LIMIT)` тепер ловиться: ключ exactRoot `(√2+…+√19)^12` справді переповнює межу в exactOf (старий тест `(√2+√3+√5)^12` межі не досягав).
   - Також `\to`, `\rightarrow`, `\leftrightarrow` — `<span class="mo">` з відступами, як «=» (з engine-render-tex-p3).
9. Коментар «a01 першою» в content/math/pool-g10-g10m5.js прибрано (лише цей рядок).
