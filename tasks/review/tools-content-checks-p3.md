### Дизайн п. 7: міжпредметне `see` на урок і екран (без коду)
Мета: учень з урока «Історії» бачить кнопку на урок іншого предмета («Всесвітня історія, 7 кл.: …»), замість тексту «Пригадай з історії України…» (writer-hist-g7s6; сьогодні лише текст). Основа вже є: `see` baseline-теми тесту рівня (CONTENT_SCHEMA §9, `baseSee`/`seeRow`/`findLesson` у app.js, `diagCtx` у lib.mjs; id уроків глобально унікальні, тож `subject` у посиланні не потрібен).
- **Поле:** `see: ["h64", "w7s2l4"]` (1–3 id уроків) — на **екрані** `info|choice|multi` (прив'язка до місця, де кажуть «Пригадай…») і/або на **уроці** (`l.see`, блок «Пов'язане» під outro). Одне поле, одна назва з тестом рівня — без другого механізму. Один id-рядок без масиву — не дозволяти.
- **Правила validate:** кожен id існує (`allLessonIds`; для чужого предмета — через `diagCtx.allLessons`); урок не старшого класу, ніж розділ-джерело (як для тесту); не сам цей урок; 1–3 елементи; без дубліката. Для `choice` з «Пригадай…» без `see` — лише поради в нотатках (не правило).
- **Рендер (app.js):** рядок-кнопка під текстом екрана («Згадати: «Назва» (Предмет, N клас)» — `seeRow`), у `outro` — перелік «Пов'язане». Назва й клас беруться з даних, не з тексту автора. Кнопка відкриває урок у режимі перегляду без впливу на прогрес (`lessonDone` не чіпаємо); повернення — туди, звідки прийшов (стек навігації). Офлайн — усе в бандлі. Якщо урок недоступний (замок класу) — кнопка з поясненням, не мовчазна.
- **Прогрес і міграція:** жодного нового поля в `slid.v1`; id — ключі прогресу (правило 11): `see` змінює лише навігацію. Рекомендація: не вмикати екранам у формулі «тест рівня»; в evidence — подія `see_open {from, to}` (за потреби).
- **Питання людині:** чи відкривати урок, закритий замком класу, у режимі «лише читати» (рекомендую так, лише `see`-посилання); чи показувати `see` у тесті рівня (ні).
- **Обсяг для engine-задачі:** validate (+ тест), app.js (рендер + навігація), CONTENT_SCHEMA §3/§4, тест у test-ui (кнопка відкриває урок, повернення).
