# PWA: змішування версій — новий зміст зі старим рушієм (порожній екран, «Перевірити» неактивна)

**Баг від людини (05.11):** u5s3l1, вправа split «Відокрем закінчення від основи» («яблунею») — екран без поля, «Перевірити» неактивна, далі не пускає.

**Причина (відтворено, scratchpad/splitbug/skew.cjs):** sw.js — навігація «мережа спершу» (нова index.html → новий список скриптів і зміст), а свої файли — `caches.match(req)` по ВСІХ кешах (знаходить app/*.js старої версії `slid-<old>`), поки новий SW ще не активний. Новий зміст + старий app.js → тип екрана невідомий рушію → renderInteractive повертає "" → порожній екран, кнопка неактивна. Сценарій: стара версія з кешем → новий деплой → перезавантаження → урок з новим типом екрана.

## Що зробити
1. **Атомарна версія в sw.js (tools/sw.template.js):** сторінка й ресурси з одного кешу — навігація з `caches.open(CACHE)` (index.html тієї ж версії), мережа — лише якщо в кеші немає; свої файли — `caches.open(CACHE).match`, не глобальний `caches.match`. Оновлення: новий SW встановлюється (precache), skipWaiting, activate → clients.claim, старі кеші видаляються.
2. **app/pwa.js:** після зміни контролера (`controllerchange`) — сторінку перезавантажити безпечно: не посеред уроку чи тесту рівня (прогрес уроку не губити) — напр. тост «Є оновлення» + перезавантаження при поверненні на головну/наступному відкритті; описати.
3. **Запобіжник у рушії (app/app.js):** якщо тип екрана невідомий рушію (render повертає ""), показати повідомлення «Онови застосунок: закрий і відкрий знову» і дозволити пропустити екран (без зарахування), а не тупик.
4. **Тест:** сценарій версійного розриву (як scratchpad/splitbug/skew.cjs: стара версія контролює → новий деплой → reload) у tools/test-ui.mjs (Node Playwright) — після виправлення екран рендериться або версія консистентна; і тест запобіжника. docs/PUBLISHING.md (оновлення PWA).
