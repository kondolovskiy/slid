# «Пишемо самі» без жодного власного тексту; «аудіювання» без звуку — потрібне рішення людини

**Рішення людини** (D-049: формат завдань і рушій — технічне питання людині; зміст — потім авторам). Агент готує дизайн-документ із варіантами (docs/design/own-writing.md) і питання людині; реалізація — окремими engine-*/write-* задачами після рішення. Скіл: за задачею; зміни коду — `engine-change`.

## Проблема
Розділи «Пишемо самі…» у 5–11 кл. обіцяють «складати оголошення», «будувати твір-роздум», «писати есе, переказ, відгук», але всі завдання — вибір готового варіанта, сортування речень, торкання слів. Жодного поля для власного речення чи абзацу. Учні 5, 6, 8, 11 кл. назвали це серед головних проблем («Писати вчаться, коли пишуть»; «на НМТ есе пишуть самостійно»). Тренувальних пулів для цих розділів немає свідомо (`NO_POOL_SECTION` у tools/lib.mjs, D-053 п. 4).

## Варіанти для дизайн-документа (не вичерпно)
1. Новий тип екрана «напиши сам» без автоматичної оцінки: поле тексту (обмеження довжини), після «Готово» — чек-лист самоперевірки (критерії з уроку) і зразок; XP за виконання, не за правильність (узгодити з D-004, D-019).
2. Напівавтоматична перевірка ознак (кількість речень, слова-зв'язки, тема) — ризик хибних вердиктів.
3. ШІ-перевірка (D-036, бекенд, engine-ai-a1) — залежить від рішень людини щодо бекенду й ПД (правило 12: збереження тексту дитини — персональні дані? → design-privacy-gdpr).
4. Аудіювання: озвучення через Web Speech API (офлайн-обмеження, якість українського голосу) або записані аудіофайли (ліцензії, розмір кешу sw.js), або чесно перейменувати на «уважне читання».
5. Мінімум без рушія: змінити назви/learned розділів, щоб не обіцяли вміння, яке не тренується.

## Критерії готовності
