# Зміна бекенду (`server/`)

Рішення — **D-037** (decisions.md); подробиці, API й відкриті питання — **docs/BACKEND.md** (прочитай перед будь-якою зміною), запуск — server/README.md.
Задача — `tasks/doing/server-*.md`; після реалізації — незалежне рев'ю (D-026, скіл `engineering-review`).

**Стек:** TypeScript, NestJS 11, PostgreSQL 16, Kysely 0.28 (не 0.29 — лише ESM), Jest + Supertest. Хостинг — Railway (`server/railway.json`). Нові залежності — лише якщо без них коду суттєво більше; точні версії, не свіжіші за ~2 тижні.

## Вимоги
1. **Офлайн-перший застосунок.** Бекенд — доповнення; фронтенд працює без нього як раніше.
2. **Мінімум персональних даних дітей.** Учень — випадковий id. Входи: анонімний токен пристрою, шкільний Google Workspace (лише `sub` і домен, дозволені домени — `GOOGLE_DOMAINS`), код прив'язки пристрою. Імені, email, телефону не зберігаємо; особисті акаунти/email дітей не приймаємо (потрібна згода батьків). SAML не потрібен. Нове поле з персональними даними — лише за рішенням людини в decisions.md.
3. **Модульний моноліт.** Модуль = `server/src/modules/<модуль>/`, публічний API — лише `index.ts`. Між модулями — порти (інтерфейс + Symbol-токен) і адаптери, не класи сервісів. Свій модуль — своя схема Postgres і свої міграції, без FK і запитів у чужу схему. Винесення модуля в сервіс = заміна адаптера, код споживачів не змінюється. Межі перевіряє `server/test/architecture.spec.ts` — **не послаблюй його**.
4. **Мінімум коду: KISS, DRY, YAGNI.** Бібліотеки замість власних рішень; абстракція — коли є другий споживач; шина подій — з першою подією. Логіку злиття прогресу не дублюємо на сервері: вона у фронтенді.
5. **TDD.** Спершу тест, що падає. Unit — на Memory-адаптерах того самого порту; e2e — лише на справжньому Postgres: без `DATABASE_URL` тест падає, а не пропускається. Регресія безпеки (токени, Google, ліміти) — тест на справжній бібліотеці, а не лише мок.
6. **Спочатку працює, потім правильно.** Перший робочий зріз → рефакторинг під патерни при зелених тестах.
7. **Безпека й дані:** токени й коди — лише SHA-256; некоректний ввід — 4xx, ніколи 500; ліміти частоти з урахуванням того, що клас школи — одна IP-адреса; `TRUST_PROXY` лише за реальним проксі.
8. **Міграції** не змінюють після розгортання — лише нова міграція; мають переживати повторний прогін і дані попередньої схеми (тест).
9. Синхронізація переносить лише `slid.v1`, не `slid.evidence.pending` / `slid.hyp`.

## Перевір (усе зелене, інакше не віддавати)
```bash
cd server
npm ci
npm run check                                  # типи + unit + межі модулів
DATABASE_URL=postgres://… npm run test:e2e     # e2e на справжньому Postgres, обов'язково
npm run build && npm run migrate && npm run migrate   # міграції з dist, повторний прогін без змін
```
