# Автор контенту: один розділ уроків

Вхід: задача `tasks/doing/<task-id>.md`. Вихід: один файл `content/<предмет>/g<клас>-<id>.js` (і, за потреби, `img/<предмет>/<id>/`).
Якщо задача ще в `tasks/todo/` — спершу `node tools/claim.mjs claim <task-id> writer-<task-id>`.

## 1. Прочитай
Задачу; docs/CONTENT_SCHEMA.md; docs/PEDAGOGY.md; style/common.md; style/<предмет>.md; style/profiles.json;
`memory/long/glossary/<предмет>.md`; `memory/long/facts/<предмет>.md`; `memory/long/pitfalls.md` (розділи «Контент і код» і про свій предмет).
Відкрий **еталонний розділ** із задачі та вже написані розділи того ж класу — повтори їхню будову, ритм і довжину. Структуру копіюй з еталона, а не вигадуй.

## 2. План і будова
- Кожна тема з плану = урок, плюс фінальний `boss` з власним значком у `sec.badges`.
- Урок: 5–10 екранів; перший — `intro` з проблемою; ≥ 50 % екранів — завдання; ≥ 2 різні типи завдань; ≥ 1 `hint`.
- Будова уроку, голос, вимоги до варіантів, `fbText`, boss — style/common.md.
- Нові id уроків і навичок; існуючі не перейменовуй (ключі прогресу).
- Історія: у кожному уроці ≥ 1 справжнє `img` (D-027) — процедура в скілі `hist-images`.

## 3. Факти
- Спершу реєстр фактів — бери формулювання й дату звідти.
- Новий факт — лише після перевірки в ≥ 2 надійних джерелах (WebSearch/WebFetch). Не вдалося — не використовуй. Не вигадуй цитат і джерел.

## 4. Чесні завдання (D-019)
Для кожного оцінюваного екрана відповідь на «Звідки учень це знає?»: попередній екран, сам екран (джерело, фото, дані, лабораторія) або міркування в 1–2 кроки.
Якщо нізвідки — додай опору перед завданням, зроби його здогадкою `hyp: true` / `poll` або прибери.
Не питай дат, імен, назв і чисел, яких ще не було. Не подавай факт уперше у `fbText`. `boss` питає лише те, що було в розділі. `cap` фото не має дослівно видавати правильний варіант.

## 5. Межі
Пиши лише у свій файл розділу, свою теку `img/` і свою задачу. Не редагуй чужі розділи, `index.html`, `style/`, `memory/long/`, `graph.js`.
Попередження validate «граф, дрейф» не виправляй у graph.js — рядок `IDEA GRAPH: …` в inbox.
Build під час паралельного запуску не запускай — це робить оркестратор.

## 6. Перевір
```bash
node tools/validate.mjs --section <id>      # 0 помилок
node tools/stats.mjs --subject <предмет>    # твої уроки без прапорців «нетипово для сім'ї» (або поясни в нотатках)
```

## 7. Здай
1. «Нотатки агента» в задачі: список уроків; усі факти з URL джерел; сумнівні місця; пропозиції до глосарію/стилю; завдання, де опора неочевидна, — з номером екрана, на який воно спирається.
2. Рядки FACT/TERM/STYLE/ENGINE в `memory/short/inbox.md` (формат — memory/README.md).
3. `node tools/claim.mjs move <task-id> review`.
4. Відповідь оркестратору — 3–6 рядків: файл, кількість уроків, результат validate, відкриті питання.
