# Незалежне рев'ю інженерних змін (D-026)

**Не той агент, що писав реалізацію.** Вхід: задача в `tasks/review/`, коміт або diff, результати перевірок автора.

## 1. Прочитай
Вимоги задачі, дизайн/документацію, на які вона посилається, і **весь** diff (`git show <коміт>` / `git diff <base>..<head>`). Перевір навколишній код і його контракти (виклики, формати збереження, тести, що зачеплено).
Для `server/` — ще docs/BACKEND.md і вимоги зі скіла `backend-change`; для `app/`/`tools/` — інваріанти зі скіла `engine-change`.

## 2. Що шукати
- Помилки поведінки й регресії; крайні випадки (порожній ввід, старі дані, відсутній модуль, немає IndexedDB/мережі).
- Втрата чи змішування збереженого прогресу (`slid.v1`, перейменовані id, міграції).
- Офлайн: застосунок без мережі, без бекенду, `sw.js` зібрано й закомічено.
- Прогалини тестів: чи падає тест без виправлення (мутуй код у копії); чи тести не прив'язані до живого змісту.
- QA-інструменти: хибні успіхи, нульові прогони, відповідність заявленого покриття реальним перевіркам.
- Бекенд: межі модулів, персональні дані, SHA-256, 4xx замість 500, незмінність міграцій.
- Документація відповідає коду.

## 3. Перевір сам
Запусти релевантні перевірки (`npm run check`, `python3 tools/test-answer-ui.py --suite regression`, `cd server && npm run check && npm run test:e2e` тощо) або відтвори підозрілий сценарій. Не видавай результати автора за власний прогін; неперевірене зазнач явно.
Мутанти й копії дерева — у власній підтеці scratchpad (не спільній з автором). Не редагуй файли реалізації паралельно з автором.

## 4. Звіт `reports/review/<task-id>.md`
- Коміт/diff, який перевірено.
- Знахідки: важливість (P1 блокує / P2 бажано до злиття / P3 потім), посилання `файл:рядок`, відтворення, очікувана поведінка.
- Виконані перевірки (точні команди й підсумки) і що не перевірено.
- Вердикт: «прийнято» або «потрібні виправлення».

## 5. Цикл
Блокувальні знахідки — автору. Автор виправляє, запускає тести й повертає diff **тому самому** рецензенту. Після повторної перевірки онови звіт (розділ «Повторне рев'ю»). Відкриті блокувальні знахідки не дозволяють перенести задачу в `done`.
