# AGENTS.md — Слід

Інструкція для ШІ-агентів (Claude Code, Codex, Cursor, Gemini). Люди: почніть з README.md.

**Слід** — офлайн-застосунок з інтерактивними уроками українською для 4–11 класів у стилі Brilliant.
Урок = послідовність коротких екранів: проблема → здогадка → теорія як відповідь → завдання з миттєвим поясненням.
Рушій (`app/`) не знає нічого про предмети; увесь навчальний зміст — у `content/` як дані.

## 0. Перед будь-якою роботою (обов'язково, у такому порядку)

1. `memory/short/handoff.md` — стан проєкту зараз і що робити далі.
2. `memory/long/INDEX.md` — що лежить у довгій пам'яті; прочитай файли, що стосуються задачі.
3. Свою задачу в `tasks/` і розділ цього файлу для своєї ролі (§4).

## 2. Команди

```bash
node tools/build.mjs                       # список скриптів у index.html + sw.js (після БУДЬ-ЯКОЇ зміни в content/, app/, img/)
node tools/validate.mjs [--section ID]     # помилки (блокують) + попередження стилю
node tools/stats.mjs [--subject hist]      # метрики складності, звіт reports/style-<предмет>.md
node tools/make-tasks.mjs [--subject math] # задачі на написання з плану
node tools/claim.mjs list|claim|move ...   # черга задач для паралельних агентів
python3 tools/playtest.py [--section ID] [--shots]   # пройти уроки в браузері
```
Скорочено: `npm run check` = build + validate + stats. Жодних залежностей для Node не потрібно; плейтесту потрібен Playwright.

## 3. Непорушні правила

1. **Мова контенту — українська**, сучасний правопис, без канцеляриту (style/common.md, style/banned-phrases.txt).
2. **Точність вища за швидкість.** Кожна дата, число, ім'я — з перевіреного джерела. Якщо не впевнений — не пиши або познач у нотатках задачі як «потребує перевірки». Вигадані цитати, «факти» і джерела заборонені.
3. **Використовуй реєстр фактів** `memory/long/facts/<предмет>.md`: якщо факт там є, бери саме це формулювання й дату. Нові факти — у нотатки задачі з джерелом, куратор перенесе їх у реєстр.
4. **Нотація й терміни — з глосарію** `memory/long/glossary/<предмет>.md` (напр. у математиці ділення «:», множення «·», дроби стовпчиком `$3/4$`).
5. **Не редагуй чужі файли.** Автор змінює лише свій файл розділу, свою теку зображень і свою задачу. Все інше — пропозицією в `memory/short/inbox.md`.
6. **Статус уроку** (`status`): `draft` → `verified` (ШІ-верифікатор) → `approved` (лише людина-вчитель). Агент ніколи не ставить `approved`.
7. **`index.html` не редагуй руками** в блоці скриптів. Під час паралельної роботи `tools/build.mjs` запускає лише оркестратор, коли всі агенти закінчили.
8. Перед тим як віддати роботу: `node tools/validate.mjs --section <id>` — 0 помилок.
9. Зображення — лише з відкритою ліцензією (docs/IMAGES.md), з підписом `cap` і записом у `credits`.

## 4. Ролі

### Оркестратор (головна сесія)
Планує, роздає задачі, запускає паралельних агентів, збирає результат.
1. Прочитай handoff, `node tools/claim.mjs list`.
2. Обери N задач одного типу (краще — один предмет і клас, щоб агенти вирівнювалися по одних еталонах).
3. Для кожної: `node tools/claim.mjs claim <task> <agent-name>` → запусти агента з промптом «Виконай задачу tasks/doing/<task>.md за AGENTS.md, роль: автор контенту». Агенти працюють паралельно — кожен у своєму файлі.
4. Коли всі завершили: `node tools/build.mjs && node tools/validate.mjs && node tools/stats.mjs && python3 tools/playtest.py`.
5. Для кожного розділу в `tasks/review/` запусти **іншого** агента-верифікатора (свіжий контекст; не того, хто писав).
6. Запусти синхронізацію стилю (роль нижче), якщо з'явилося ≥ 3 нових розділів одного предмета.
7. Наприкінці — роль «куратор пам'яті» (`/handoff`).

### Автор контенту (content-writer)
Вхід: задача `tasks/doing/write-*.md`. Вихід: один файл `content/<предмет>/g<клас>-<id>.js`.
1. Прочитай: задачу, style/common.md, style/<предмет>.md, глосарій і реєстр фактів предмета, pitfalls.md, **еталонний розділ** із задачі та вже написані розділи того ж класу.
2. Склади план уроків (кожна тема з плану = урок, плюс фінальний `boss`). Кожен урок: 5–10 екранів, перший — `intro` з проблемою, ≥ 50 % екранів — завдання, ≥ 2 різні типи завдань, ≥ 1 `hint`.
3. Пиши за схемою docs/CONTENT_SCHEMA.md. Скопіюй структуру з еталона, а не вигадуй нову.
4. `node tools/validate.mjs --section <id>` → 0 помилок; `node tools/stats.mjs --subject <предмет>` → твої уроки без прапорців «нетипово для сім'ї» (або поясни в нотатках, чому так треба).
5. У нотатках задачі: перелік фактів з джерелами (URL), сумнівні місця, пропозиції до глосарію/стилю.
6. Допиши один рядок у `memory/short/inbox.md` (формат там) і `node tools/claim.mjs move <task> review`.

### Верифікатор (content-verifier)
Незалежна перевірка. **Не той агент, що писав.** Вхід: задача в `tasks/review/`.
1. Факти: кожне твердження з датою, числом, іменем, назвою — звір із ≥ 2 надійними джерелами (енциклопедії, офіційні сайти ЮНЕСКО/ООН/ВРУ, академічні видання). Відкрий, а не згадуй.
2. Відповіді: для кожного завдання розв'яжи сам, не дивлячись на `correct`, і порівняй. Перевір, що неправильні варіанти справді неправильні і не двозначні.
3. Педагогіка й вік: проблема → теорія; пояснення «чому»; немає пасток без підказки; немає лякаючого чи неприйнятного для віку змісту.
4. Звіт `reports/verify/<id>.md`: таблиця «що перевірено → джерело → вердикт», список виправлень (критичні / бажані).
5. Критичні помилки (хибний факт, неправильна відповідь) — виправ сам у файлі розділу й зазнач у звіті. Якщо урок чистий — `status: "verified"`.
6. Перевірені факти — рядками в inbox (куратор перенесе в реєстр). `node tools/claim.mjs move <task> done`.

### Синхронізатор стилю (style-sync)
Стежить, щоб уроки одного предмета не різнилися стилем і складністю.
1. `node tools/stats.mjs --subject <предмет>` і прочитай `reports/style-<предмет>.md`.
2. Для уроків з прапорцями порівняй з еталоном (style/<предмет>.md → «Еталони») і сусідами того ж класу.
3. Дрібне (довжина речень, заборонені фрази, бракує hint) — створи задачу `tasks/todo/style-*.md` або виправ сам, якщо урок ще `draft`.
4. Системне (профіль застарів, треба нове правило) — запропонуй зміну `style/` через inbox із цифрами; змінює лише людина або куратор після рішення в decisions.md.

### Куратор пам'яті (memory-curator)
Наприкінці сесії або після паралельного запуску.
1. Прочитай `memory/short/inbox.md` і нотатки закритих задач.
2. Перевірені факти → `memory/long/facts/<предмет>.md`; нові терміни → glossary; повторювані технічні проблеми → pitfalls.md; ухвалені людиною рішення → decisions.md.
3. Суперечності (два агенти, різні дати) — не вирішуй сам: винеси в handoff як «відкрите питання».
4. Очисти inbox (перенесене видали), запиши журнал `memory/short/sessions/<дата>-<n>.md`, перепиши `memory/short/handoff.md`.

## 5. Паралельна робота: як не заважати одне одному

- **Одиниця паралельності — розділ.** Один агент = одна задача = один файл розділу.
- Задачу бере лише `tools/claim.mjs claim` (атомарне перейменування файлу; друга спроба отримає помилку).
- Спільні файли (subjects, plan, style, memory/long, index.html) під час паралельного запуску **ніхто не змінює**; усе — через inbox.
- Щоб 5 авторів писали однаково: однакові еталони в задачах, спільний профіль складності, після запуску — style-sync. Докладніше: docs/WORKFLOW.md.

## 6. Готово означає

- `node tools/build.mjs` запущено, `index.html`, `sw.js`, `content/manifest.json` закомічені (інакше CI не опублікує, а PWA не оновиться).

- `node tools/validate.mjs` — 0 помилок; `python3 tools/playtest.py --section <id>` — зелено.
- Уроки розділу без прапорців у stats або з поясненням.
- Задача в правильній теці, нотатки заповнені, рядок в inbox.
